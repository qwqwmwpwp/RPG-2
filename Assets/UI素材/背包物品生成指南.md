# 背包物品素材与数据生成指南

本指南按当前背包的 `ItemManifest`、片段结构和 UI 读取方式整理，适用于武器、护甲、披风、消耗品、材料等物品的图标及配套数据生成。

每种物品以一个 `ItemManifest` 资产定义，用片段组合占格、图标、说明及可选能力。一个物品可以占多格；图标画布随占格比例变化，不统一压成正方形。新增内容复用现有结构，缺少依据的玩法属性不自动补写。

## 1. 生成前确定的输入

| 输入 | 要求与用途 |
| --- | --- |
| 中文名称、英文标识 | 中文名称用于清单资产名；英文标识用于图标、预制体文件名及标签分段。 |
| 物品类型 `itemType` | 唯一、稳定的完整标签；决定目录查找及详情分类。 |
| 占格宽高 `W × H` | 均为正整数；根据物品形态和设计确定，优先沿用已有物品配置。 |
| 外观参考 | 已有模型、材质、贴图、参考图的实际路径；列出必须保留的轮廓、结构和颜色。没有参考时明确采用文字设计。 |
| 风格、朝向、材质变体 | 卡通或写实、横向或纵向等；同一批素材保持光照和表现一致。 |
| 中文说明 | 只写已有外观、用途或已确认属性；不把设想写成已实现功能。 |
| 堆叠、装备、消耗及数值 | 按物品需要提供；装备须核对预制体与实际挂点，数值须有用户或项目配置依据。 |

标签使用点号分段，各段仅含 ASCII 字母、数字和下划线；不含中文、空格、空段，也不以点号开头或结尾。目录按区分大小写的完整字符串匹配。

当前详情界面识别以下分类前缀：

| 类型前缀 | 显示分类 |
| --- | --- |
| `GameItems.Equipment.Weapons` | 武器 |
| `GameItems.Equipment.Armors` | 护甲 |
| `GameItems.Equipment.Cloaks` | 披风 |
| `GameItems.Consumables` | 消耗品 |
| `GameItems.Craftables` | 材料 |

其他前缀显示为“物品”；带有 `ConsumableFragment` 的物品也可被识别为消耗品。新增物品优先使用已有分类。独立入包的外观变体分别使用唯一标签和清单；仅修改同一物品的图标时沿用其身份。

## 2. 图标画布与视觉规范

新素材统一采用 **256 × 256 像素/格** 制作标准：

```text
最终 PNG 宽度 = W × 256
最终 PNG 高度 = H × 256
画布宽高比 = W : H
```

| 占格 | 最终 PNG 尺寸 | 构图参考 |
| --- | --- | --- |
| 1 × 1 | 256 × 256 | 紧凑物品居中 |
| 1 × 2 | 256 × 512 | 纵向完整展示 |
| 2 × 2 | 512 × 512 | 较宽物品或护甲 |
| 2 × 3 | 512 × 768 | 竖向长物品 |
| 4 × 2 | 1024 × 512 | 横向长物品 |

表中尺寸是新素材制作示例，不要求迁移已有物品。256 是素材分辨率基准，**不是屏幕上每格的固定显示尺寸**；最终显示由现有背包 UI 的格子尺寸与缩放控制。

- 输出 PNG，使用真正的 RGBA 透明背景；镂空部位按参考正确透空，不绘制棋盘格或白底冒充透明。
- 一张图展示一个物品条目。堆叠数量由 UI 显示，不为表达可堆叠而重复绘制多个物体；设计本身是成束、成盒物品时保留其整体结构。
- 保持完整轮廓、正确比例及结构细节；居中等比例构图，建议四周留约 5%～8% 安全边距，细长物体按自身形状自然留白。
- 横向占格优先横向展示，纵向占格优先纵向展示。角度以轮廓可读和充分利用画布为准，不固定具体角度，也不依赖运行时旋转来纠正构图。
- 使用清晰的游戏物品插画、适度体积和统一的左上柔光；暗色材质可有克制的边缘提亮，缩小后仍能辨认轮廓。卡通与写实只改变表现和材质，不随意改变参考造型。
- 图内不绘制网格、底板、边框、稀有度色框、徽章、文字、数字、水印、场景或物体外部投影；这些界面信息交给现有 UI。
- 生成器未直接输出目标尺寸时，可在保留 alpha 的前提下等比例缩放并补透明画布；禁止非等比拉伸、裁掉主体或修改结构来凑尺寸。先正确构图，再适配画布。

### 通用生成提示词

先把所有占位符替换为本物品的具体值；尺寸由占格计算。使用支持透明输出的生成工具时，同时启用透明背景参数；仅写提示词不能替代实际 alpha 检查。

```text
Asset type: production Unity RPG inventory item sprite.
Create one isolated inventory item: {item_name_and_object_description}.

Reference: {reference_image_roles_or_text_design}.
Faithfully preserve {required_silhouette_proportions_structures_and_colors}.
Do not substitute a generic item or invent extra components.

Inventory footprint: {W} cells wide by {H} cells high.
Each source-art cell is 256 by 256 pixels.
Target final PNG: {W_times_256} by {H_times_256} pixels;
canvas aspect ratio: {W}:{H}.
Composition: {horizontal_vertical_or_compact_orientation_and_view_angle}.
Center the complete item, keep its original proportions and all parts visible,
use the canvas efficiently, and leave approximately 5 to 8 percent safe margins.
Never stretch the item or crop parts to fit.

Finish: {stylized_or_realistic_game_inventory_illustration}.
Material variant: {material_colors_surface_finish_and_reference_constraints}.
Crisp readable silhouette, controlled shading, coherent soft upper-left light,
restrained edge highlights readable over a dark inventory panel.

Real RGBA transparent background, including all intended openings.
No background, floor, external cast shadow, glow, colored halo, grid,
UI panel, border, badge, lettering, numbers, watermark, people,
or accessories not present in the design.
```

有参考图片时注明各张图的用途；只有模型路径时，需先取得实际参考图，不能假设图像生成器能读取本地模型路径。需要优化已有图标时，使用下列编辑补充，并明确编辑目标图和辅助参考图：

```text
Input image 1 is the existing item icon to edit.
{roles_of_any_additional_reference_images}
Reframe this same item for the specified inventory footprint and orientation.
Preserve its design, proportions, material variant and intended transparency.
Change only {requested_composition_or_readability_adjustment}.
Do not redesign, add components, clip parts or distort the item.
```

## 3. Unity 图标导入配置

| 设置 | 新素材采用的值 |
| --- | --- |
| Texture Type / Sprite Mode | Sprite (2D and UI) / Single |
| Mesh Type / Pivot | Full Rect / Center，`(0.5, 0.5)` |
| Pixels Per Unit | 256，与素材每格制作基准一致 |
| Max Size | 不小于图片长边；选取足够大的档位，例如 1024 × 512 使用 1024 |
| Non Power of 2 | None，避免 512 × 768 等画布被自动改尺寸 |
| Filter Mode / Wrap Mode | Bilinear / Clamp |
| Alpha | 使用输入 alpha，开启 Alpha Is Transparency |
| Generate Mip Maps / Compression | 关闭 / None；平台覆盖也不得意外缩小或压缩 |

PNG 的宽高、导入设置及 `GridFragment` 的比例应一致。PPU 不负责控制当前背包中物品的屏幕显示大小。

## 4. 物品清单与片段映射

清单类型为 `RPG4.Backpack.Items.ItemManifest`，由 `itemType` 和 `fragments` 组成。片段的命名空间与程序集均为 `RPG4.Backpack.Items`。下表使用实际序列化字段名，适用于生成或核对 `.asset` 数据。

| 片段 | 字段与配置规则 | 使用条件 |
| --- | --- | --- |
| `GridFragment` | `width = W`、`height = H`，均 ≥ 1；`padding` 为非负有限数，新物品通常沿用 0。固定标签 `FragmentTags.Default.GridFragment`。 | 新物品明确配置占格；缺省时框架按 1 × 1 处理。 |
| `ImageFragment` | `icon` 引用实际导入的 Sprite；新素材约定 `iconDimensions = (W × 256, H × 256)`。固定标签 `FragmentTags.Default.IconFragment`，不能误写为 `ImageFragment` 标签。 | 需要显示图标的物品。 |
| `TextFragment` | `fragmentTag` 使用已有 `FragmentTags.Default.Description`；`text` 为中文说明。 | 需要补充说明时。 |
| `StackableFragment` | `maxStackSize` 为整数且 ≥ 1。固定标签 `FragmentTags.Default.StackableFragment`。 | 需要堆叠时添加；缺少此片段即不可堆叠，上限为 1。 |
| `EquipmentFragment` | `equipmentType` 为合法非空装备类型标签；`equipPrefab` 引用实际模型预制体；`socketAttachPoint` 核对角色挂点；`modifiers` 保存已确认的装备数值项，可为空列表。固定标签 `FragmentTags.Equip.EquipmentFragment`。 | 物品有已确定的装备配置时。 |
| `ConsumableFragment` | `modifiers` 保存已确认的 `ConsumeModifier`，可为空列表。固定标签 `FragmentTags.Consumable.ConsumableFragment`。 | 物品有已确定的消耗配置时。 |
| `LabeledNumberFragment` / `EquipModifier` / `ConsumeModifier` | 使用语义对应的自定义 `fragmentTag`，配置 `label`、`value`、`min`、`max`、`randomizeOnManifest` 及显示选项。 | 有明确数值来源时；装备与消耗数值项分别放入对应容器。 |

`iconDimensions` 是现有图像片段的配置字段。当前背包物品框读取 Sprite 并按物品框可用区域等比例适配，未使用 `iconDimensions` 决定占格或屏幕大小；`padding` 也不应被当作素材像素边距。无需为采用新素材标准而批量重写旧数据。

数值字段必须为有限数，`min ≤ max`。固定数值可设置 `value = min = max`、`randomizeOnManifest = false`；有随机需求时按已确认区间配置，随机化发生在创建运行时实例时。`collapseLabel`、`collapseValue` 控制显示，`minFractionalDigits ≥ 0` 且 `maxFractionalDigits ≥ minFractionalDigits`。当前详情支持显示数值与说明，不代表对应玩法效果已经接入。

常见组合：材料使用网格、图标及按需说明和堆叠；消耗品在基础片段上添加消耗配置；装备在基础片段上添加装备配置。不要仅根据物品图像推测数值或补造玩法逻辑。未知的可选配置先省略；若它是本次目标必需的数据，则标明缺失信息后再补齐。

### 名称、标签与引用

- 当前名称从目录命中的 `ItemManifest.name` 读取，即清单资产名；`TextFragment` 用于说明。不要添加框架不存在的 `displayName`、`rarity`、`price` 等字段并声称会被 UI 自动识别。
- 物品清单放入 `Assets/backpack/Data/Items/<分类>/`，可沿用已有目录；图标放入 `Assets/UI素材/<分类>/`。推荐图标名 `Icon_<物品英文标识>_<变体>.png`，无变体时省略后缀。
- 装备预制体放入 `Assets/backpack/Prefabs/` 下对应分类的实际目录。复用已有模型时保留其比例、变换、材质槽及约束，只修改本次明确要求的内容；挂点名称按对应角色的实际配置填写。
- 将新增清单追加到 `Assets/backpack/Data/Items/物品清单目录.asset` 的 `manifests`；每个完整 `itemType` 只对应一份清单，重复标签查找时只保留第一条。
- 将新增的完整物品标签及需要使用的自定义片段标签登记到 `Assets/backpack/Data/TagRegistry.asset`，避免重复。注册表提供合法性检查和编辑候选；父节点无需全部登记，也不替代清单目录。
- `fragments` 与容器内 `modifiers` 使用 Unity `SerializeReference`。写入 YAML 时保持 `rid` 与 `references.RefIds` 对应、类型及程序集准确；使用实际 `.meta` GUID 和目标对象 fileID，不复用别的资产 GUID，不把示例占位符写入生产数据。标签字段按现有 `{ name: 完整标签 }` 结构序列化。

## 5. 可复用的物品生成任务模板

复制后填写具体值；这是交给生成执行者的任务描述，**不是项目能够直接导入的 JSON 或新增数据结构**。批量生成时，每个独立物品或变体填写一份；本节不要求额外交付文档或提示词记录文件。

```text
按《背包物品素材与数据生成指南》生成并接入以下物品：

物品名称：{中文名称}
英文标识与变体：{英文标识；无变体写“无”}
物品分类及 itemType：{分类；唯一完整标签}
背包占格：{W} × {H}
参考模型、材质、贴图及图片：{实际路径；无参考则提供文字设计}
必须保留的造型：{轮廓、比例、关键结构及颜色}
插画风格与展示方向：{卡通/写实；横向/纵向；视角}
材质表现：{颜色、质感、允许的磨损和高光}
中文说明：{已确认的说明文本}
堆叠：{不可堆叠，或最大数量}
装备：{不适用，或装备类型标签、实际预制体、角色挂点、数值项}
消耗：{不适用，或已有消耗数值项及其处理依据}
其他属性：{无，或已确认的标签、数值/区间、随机及显示设置}
资源输出目录：{图标、清单及必要预制体的实际目录}

图标使用 256 像素/格标准，最终 PNG 为 W×256 乘 H×256，
采用正确占格比例、真实透明背景、完整轮廓和等比例构图。
按需要组合现有片段，登记清单目录及标签注册表，维护正确引用。
缺少数值或功能依据时不自行补造；必要信息缺失时明确指出。
完成与本次生成相关的静态核对；Unity 导入、显示及交互由人工确认，
只有用户明确要求时才由代理启动 Unity 或进行直接测试。
```

## 6. 验证

生成后先静态核对 PNG 实际尺寸、alpha、占格比例、片段类型与标签、GUID/fileID、预制体和材质路径、清单目录唯一性及标签登记。图像能否辨认、是否裁切或有白边，需要实际查看生成图；不能仅凭提示词宣称通过。Unity 内的导入结果、深色背包上的显示、详情名称与说明、堆叠及其他相关交互留给人工确认，未执行的验证如实注明。
