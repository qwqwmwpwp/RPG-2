# 网络权威处理与部署方向

更新日期：2026-11-01。以当前工作区实现为准；应用入口与完整会话流程见[游戏运行流程图](游戏运行流程图.md)，角色内部流程见 [Player 组件架构与调用时序](Player组件框架与调用时序.md)。

## 部署目标与现状

**当前产品入口是纯客户端连接独立服务器；Host 与旧离线流程保留兼容，单人迁移到 Host 仍是后续目标。**

默认客户端构建场景依次为 `ClientBootstrap → MainMenu → OnlineGame`，登录使用受信任服务器目录与账号认证。`ClientSessionController` 负责连接、认证、场景加载、等待角色、游戏中及断线清理；仅在角色与界面就绪后放行本地输入，清理完成后返回菜单。独立服务器使用单独构建列表 `ServerBootstrap → OnlineGame`，先校验部署配置、已有密钥和数据库，再启动网络并等待世界就绪。

旧 `Main` 不在当前客户端构建列表中，其默认启动模式仍为 `None`，保留旧离线角色及手动 Host 路径。下图描述复用的权威管线，其中 Host 为兼容能力，不是当前主菜单登录流程。

```mermaid
flowchart LR
    Dedicated["独立服务器进程"] --> Authority["共用权威管线<br/>角色、战斗、库存"]
    Host["Host 进程<br/>服务器 + 本地客户端"] --> Authority
    Host --> Local["本地玩家输入"]
    Remote["远程客户端输入"] --> Gateway["连接与归属校验"]
    Local --> Buffer["对应角色输入缓冲 / 事务队列"]
    Gateway --> Buffer
    Buffer --> Authority
    Authority --> Result["已提交状态与结果"]
    Result --> Client["客户端表现与 UI"]
```

Host 本地玩家直接使用权威结果，不再运行客户端移动预测。当前主菜单通过已配置的受信任端点加入独立服务器；单人仅本地连接策略、局域网自动发现与加入、主机迁移均尚未完成。

## 权威 Tick

`NetworkPlayerSimulation` 在每个 Unity 固定步只推进一次，角色按 `netId` 排序；当前默认步长为 0.02 秒。

```mermaid
flowchart TB
    Input["采样 Host 输入<br/>远程输入已由网络入口缓冲"] --> Operations["执行各角色本轮事务<br/>背包、装备、武器操作"]
    Operations --> Move["每角色最多消费一份按序输入<br/>动作与移动；接受射击并扣弹入队"]
    Move --> Physics["全部角色移动完成<br/>同步物理变换、捕获战斗历史"]
    Physics --> Combat["统一结算待处理射击<br/>命中与伤害"]
    Combat --> Publish["刷新角色发布状态<br/>捕获网络快照与结果事件"]
    Publish --> Send["排队复制"]
```

数据包只增加待处理输入，不增加模拟步数。装备事务先于开火，已接受射击不因随后死亡而撤销；跨容器事务由库存核心统一提交或回滚。远程命中回溯由服务器测得的 RTT 与配置决定，Host 本地回溯延迟为零。

## 复制与发送预算

```mermaid
flowchart TB
    Result["权威结果"] --> Scope["按所属、空间 AOI、访问订阅<br/>选择接收者"]
    Scope --> State["角色状态 + 输入确认<br/>不可靠；合并为最新值"]
    Scope --> Shot["射击反馈<br/>不可靠；独立事件、有有效期"]
    Scope --> Shared["共享容器内容<br/>可靠分片"]
    State --> Budget["NetworkSendScheduler<br/>每连接预算与等待排序"]
    Shot --> Budget
    Shared --> Budget
    Budget --> Flush["LateUpdate.Flush<br/>发送前再次校验"]
    Scope --> Direct["私人库存、装备、事务结果<br/>各自可靠同步路径"]
```

- 所属玩家快照优先；等待过久的项目按截止时间优先，预算不足仍会延后。预算只覆盖已接入的载荷，不是总带宽上限。
- AOI 按场景、网格与变化标记更新观察者，仍有周期扫描。看见容器外壳不代表可以读取内容。
- 客户端收到快照后校正所属角色或插值远端角色；不复制整块黑板，也不重放武器和物品事务。角色静止降频、字段差量与量化仍未实现。

## 库存增量

```mermaid
flowchart LR
    Change["权威物品变化"] --> Projection["InventoryNetworkProjection<br/>变更跟踪与缓存"]
    Projection --> Kind{"结构或布局改变？"}
    Kind -->|是| Full["完整条目<br/>结构基线 + 运行状态"]
    Kind -->|否| Runtime["运行字段 SET<br/>耐久、膛内弹药、射击序号、剩余弹数"]
    Full --> Stream["InventorySyncList<br/>有序版本与安全合并"]
    Runtime --> Stream
    Stream --> Mirror["InventoryNetworkMirror<br/>整批校验后提交；结构相同可复用实例"]
```

混装弹序保存在结构基线中；仅消耗弹药可发运行差量，增加或重排弹药须更新结构。完整恢复同时需要结构与运行载荷。

## 共享容器访问

```mermaid
flowchart TB
    Open["请求打开容器"] --> Check{"归属、存活、场景、距离<br/>观察权限与配置许可通过？"}
    Check -->|否| Reject["拒绝访问"]
    Check -->|是| Session["建立访问会话"]
    Session --> Version{"订阅者版本连续？"}
    Version -->|首次或历史缺失| Baseline["捕获完整基线"]
    Version -->|连续| Delta["取下一批增量"]
    Baseline --> Chunk["按预算发送分片<br/>每次发送前复核权限"]
    Delta --> Chunk
    Chunk --> Apply["收齐并校验批次<br/>更新镜像；首次基线完成后开放 UI"]
    Session -.->|关闭或权限失效| Revoke["撤销会话、取消待发、清理镜像"]
```

每片载荷为 1 KiB。慢订阅者缺失历史时恢复完整基线；在途基线先发完，再追赶变化。旧会话分片被忽略，损坏或不连续批次会关闭访问；取放物品还须在事务执行时再次校验权限。

## 单人 Host 迁移

```mermaid
flowchart LR
    Policy["定义单人会话<br/>仅本地连接、暂停、存档与退出"] --> Pickup["补齐权威散落物拾取"]
    Pickup --> Lifecycle["统一玩家生成与数据恢复<br/>迁移单人入口到 Host"]
    Lifecycle --> Verify["基础运行验证"]
    Verify --> Remove["移除旧离线调度<br/>立即射击结算与旧角色恢复分支"]
```

当前仍需保留的边界：

- `WorldPickup` 拒绝网络会话拾取，包括 Host；不能只改默认启动模式。
- 旧 `Main` 的联机启停会暂停、恢复旧离线角色，不自动转移位置、背包与装备；停止 Host 不回滚共享箱子。新的在线入口启用 `GameplaySceneBindings`，不恢复旧离线替身，客户端断线后清理会话并返回主菜单。
- 纯客户端只预测移动，完整受击方向事件未复制；调度器目前推进已注册网络角色，不是通用 AI / 世界循环。
- 多客户端争抢、回溯、丢包校正、预算拥塞与分片恢复的运行效果及实际带宽，不能由静态文档核对确认。
