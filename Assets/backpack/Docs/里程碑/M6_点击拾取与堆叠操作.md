## 二、与蓝本的差异

1. **视图来源**：蓝本的弹窗与描述面板由 `InventoryPanelFactory` 运行时构建；RPG_4 改为序列化引用 + 用户手搭（见第三节），`InventoryPanelFactory` 未移植，回折定位改用既有 `GridUtils.GetClampedWidgetPosition`。
2. **点击来源**：蓝本直读 `Mouse.current.leftButton/rightButton`；RPG_4 由输入宿主 `InputManager` 提供的 `backpack/leftButton`、`backpack/rightButton` 动作推给 `PushClick(int)` 入队，`Update` 按网格几何统一分派。鼠标坐标走 `backpack/pointerPosition`、ESC 走 `backpack/cancel`（见第二节第 15 条；改动前这两处是 UI 侧直读设备）。窗口关闭或指针被面板拦截时，排队中的点击会被丢弃（与蓝本「当帧直读」等价）。
3. **主控职责合并**：RPG_4 的 `BackpackGridUI` = 蓝本 `InventoryGridView` + `MenuView` + `HudView` 的合并体，因此 `TryGetItemView + SlottedItemView.SetHovered` 改为 `SetItemHovered(ItemId, bool)`（物品框内部结构不外露），`Render(snapshot)` 改为 `Redraw()`（快照由主控自己维护）。
4. **装备槽分支未落**：蓝本 `HandlePrimaryClick` 里装备槽优先于网格，RPG_4 留在原处只留注释，M7 接入装备栏时直接填充。
5. **诊断字段未移植**：蓝本的 `SplitRejectionCount` / `LastSplitResult` 未搬（RPG_4 用既有 `DesyncCount` / `LastError` 与日志口径，不留无人读的状态）；拆分失败只记 Warn 日志，与 `CmdRequestSetStackCount` / `CmdRequestRemoveItem` 一致。
6. **坐标口径含间距**：M5 的格子带 `slotSpacing`，`TryResolveTile` / 预览定位 / 物品框尺寸全部按「格数 × cellSize + 间隔 × (格数 − 1)」换算（蓝本无间距）。
7. **未启用死键**：`Ui.GridSlotClicked` / `Ui.Popup.Split` 在蓝本运行时零调用，RPG_4 同样不接线。
8. **弹窗数量**：蓝本口径为「跨次保留上次数量，仅做 1..堆叠数 夹取」；右键拆分落地后弹窗不再接线（见第 13 条），该口径只在重新接线时才需要关心（`BackpackItemPopupView.Show` 里那一行）。
9. **描述面板背景**：`raycastTarget` 必须为 true（以蓝本代码为准，蓝本文档写成 false），交互层据此调用 `ContainsScreenPoint` 跳过网格分派。
10. **不留无人读的诊断 API**（修正项 J 的口径）：蓝本控制器的诊断属性（`IsCarrying` / `CarriedItemId` / `CurrentTile` / `CurrentSpaceQuery` / `CurrentTargetIndex` / `CurrentHoverState` / `LastRejection`）与代码注入入口 `Configure`、弹窗的 `Target` / `SplitCount` / `TargetItemId`、描述面板的 `DescribedItemId`、`ItemDescriptionContent.Rows`、主控的 `ManualPositions` / `ClearManualPositions`、调色板的面板色（`PanelBackground` / `PanelBorder` / `Accent` / `Danger`）全部未移植；被拒绝的原因只走 `BackpackLog.Warn`，需要时再加回。
11. **抓取锚点改为「点击格偏移」**（2026-10-06 用户选型，改动落在 `BackpackInteractionController` + `BackpackGridUI`）：蓝本每帧按「悬停格象限 + 取物品中心格」推导上左索引（`GetUpperLeftIndex(index, quadrant, dimensions)`），拾起瞬间预览与落点必然跳位（2×3 物品偏 1 格，偶数尺寸还随象限抖动）。RPG_4 改为在 `BeginCarry` 记录一次抓取格偏移（`carriedGrabOffset` = 被点击格 − 物品上左格，由 `GetGrabOffset(placement.Position)` 用本帧点击格算出；点击格非法时回退 `(0,0)`），此后落点 = 悬停格 − 偏移，被点击的那一格始终贴住光标。`GetUpperLeftIndex(int hoverIndex, Vector2Int grabOffset)` 不再吃象限，换算改走 `GridUtils.GetPositionFromIndex / GetIndexFromPosition`（满足 F4 §5）。口径：锚格越界返回 `NoIndex`（不夹取、保持携带），区域越出网格仍由 `QuerySpace` 判 `Blocked`；`ApplyRegionHighlight` 由「整块越界即放弃着色」改为「裁剪到网格内着色」，使贴边外伸时网格内部分照常显示阻塞红。`TrySetCarriedPreviewScreenPosition` 由「物品半尺寸居中」改为「被点格中心对准光标」（第三参数由 `GridCoord dimensions` 换成 `Vector2Int grabOffset`），与网格内贴格同口径，出入网格不跳位。F3 的 `TileQuadrant` / `TileParams.Quadrant` 契约保留（`TryResolveTile` 照旧判定、`TileParams.IsValid` 仍依赖象限非 `None`），只是不再参与落点推导。
12. **共享核心抽取后的归属变化**（2026-10-06）：三个 `Cmd.*` 意图的订阅与分发、拆分编排（快照恢复 / 行优先找空位 / 失败回滚）、联机服务端的堆叠修改 / 移除 / 拆分复核全部收进 `InventoryHostCore`（`Scripts/Inventory/`，单机与联机宿主组合同一份实现），双方公开 API 与外部接线不变。联机服务端「设置堆叠数」由直改 `RuntimeItem` 统一为容器 `TrySetStackCount`（推进 Revision 并广播，修复主机端界面收不到 `Inv.Changed` 的缺口）；服务端物品查找由「投影优先 + 扫描回退」统一为容器直查；`Cmd` 层不再重复记拒绝日志。
13. **右键拆分 + 弹窗下线**（2026-10-06 用户选型，改动落在 `BackpackInteractionController` + `BackpackGridUI`）：
    - **弹窗整条链路下线**：删除 `BackpackInteractionController` 的 `popup` 字段、`PopupDismissDelay` / `popupLeftSince` / `popupEngaged` / `UpdatePopupLifetime`，以及 `RequestSplit` / `RequestDrop` / `RequestConsume`（届时已无调用者）；`BackpackItemPopupView.cs` 与 `.meta` **保留但不接线**（避免丢失沿用蓝本的 GUID 与场景已挂节点，其 `Awake` 自行收起面板、无 `Update`，留着无副作用），`UiChannels.PopupSplit` 死键与 `Cmd.Item.Drop` / `Cmd.Item.Consume` 频道原样保留给 M8。
    - **右键 = 拆 1 个到鼠标**：对可堆叠且数量 > 1 的悬停物品右键 → 进入**虚拟部分携带**，只在本机记 `carriedCount`，源物品仍留原格并用「显示数量覆盖」显示「总数 − 已取」，预览显示 ×N，**不写任何库存数据**（无网络往返、无闪位）。
    - **累加**：指针停在**同一源物品**上再右键即再取 1 个，直到取满整堆；取满后源物品隐藏、落点分派退化为原有整件携带口径（`PlaceAt` / `ResolveStackOrSwap` / `SwapPositions`）。其它位置右键无操作，取消只按 ESC（整件携带仍保留「右键取消」，M6 原验收第 8 条不受影响）。
    - **落点分派**：全空 → 提交一次 `Cmd.Item.Split(源, 已取数量)`，等 `Inv.Changed` 回传后按「新增 + 同类型 + 数量相符」认领该实例并写进本机位置表（位置不上网，认领跨帧重试，0.5s 超时放弃并记 Warn）；落回源物品自身 → 放回取消；落点为同类可堆叠 → `room ≥ N` 全并入 / `0 < room < N` 部分填充（目标 +room、源 −room），两者都提交 `SetStackCount`；目标已满 / 异类 / 多物品挡路 / 越界 → 这 N 个退回源堆叠（零数据写入）。
    - **防闪帧**：提交类路径把源物品的显示覆盖保留到数据回传——主控 `Refresh` 按「真实堆叠数 ≤ 覆盖值即自愈丢弃」，1s 超时兜底还原真值，故主机端与纯客户端都不出现「先跳回原值再变动」。
    - **未改**：`BackpackNetworkInventory` / `InventoryHostCore` 与拆分协议、`UiChannels` 契约。
14. **主控物品列表重读补齐**（2026-10-06 缺陷修复，`BackpackGridUI.Refresh`）：自研主控把蓝本的 `Render(snapshot)` 改成「自维护快照」时漏了重取列表——`snapshot` 原先只在 `BindInventory` 填一次，而 `RuntimeItem` 是活引用，于是堆叠数变化能显示、**增删物品却永远不反映**（拆分出的新实例画不出来、被移除的源物品不消失、认领因 `itemsById` 里没有新标识而必然超时）。现改为 `Refresh` 每次入口 `Inventory.CopyItems(snapshot)`（数据源未绑定即跳过），删掉 `BindInventory` 里那次冗余拷贝；代价是每次重绘一次列表拷贝（主机端 = 容器按标识填充，纯客户端 = 镜像值 + 排序），重绘只发生在绑定 / `Inv.Changed` 置脏的帧末 / 本地状态变化，不逐帧。
15. **输入来源收归单一宿主**（2026-10-06 用户选型，改动落在 `Assets/Scripts/Input/` + `BackpackGridUI` + `BackpackInteractionController` + `New Scene.unity`）：
    - **动机**：`Assets/input/` 原先没有 asmdef，`InputManager` 与生成类 `InputActions` 落在 `Assembly-CSharp`，而 asmdef 程序集**无法**引用预定义程序集——`RPG4.Backpack.UI` 里的 `BackpackGridUI` 根本看不见 `InputManager`，直接改会编译失败。因此新建 `Assets/Scripts/Input/RPG4.Input.asmdef`（只引用 `Unity.InputSystem`、`rootNamespace = RPG4.Input`），输入代码整体迁入该目录，`RPG4.Backpack.UI.asmdef` 的 `references` 追加 `RPG4.Input`（单向引用，`RPG4.Input` 不引用任何 `RPG4.Backpack.*`，无循环）。
    - **输入资产原地不动**：`InputActions.inputactions` 仍在 `Assets/input/`，只是把 importer 的 `wrapperCodePath` / `wrapperClassName` / `wrapperCodeNamespace` 设为 `Assets/Scripts/Input/InputActions.cs` / `InputActions` / `RPG4.Input`，生成类随之落到新目录并带命名空间（Unity 下次导入会按同一资产重新生成，内容与手写件一致，自愈不漂移）。
    - **映射所有权收归宿主**：`InputManager` 独占 `Enable` / `Disable` / `Dispose`（`backpack` 映射常驻启用），消费方只 `+=` / `-=` 回调。改动前 `BackpackGridUI.UnbindInputActions()` 会 `backpackMap.Disable()`，映射一旦共享就会把别人的映射一起关掉，故该调用被删除。
    - **缺失降级**：`InputManager.Instance == null`（忘挂场景 / 尚未 `Awake` / 已销毁）时只记一条 Warn 且**不做输入回退**，背包无按键与鼠标响应、界面照常显示；`BackpackGridUI` 用 `inputBound` 标志在 `Update` 里逐帧重试，宿主销毁时主动退订悬挂的动作。宿主加 `[DefaultExecutionOrder(-1000)]` 保证早于 UI 的 `OnEnable` 就绪，并 `DontDestroyOnLoad` 常驻。
    - **新增两个动作**：`cancel`（Button，`<Keyboard>/escape`）与 `pointerPosition`（Value / Vector2，`<Mouse>/position`）。`BackpackInteractionController` 由原先直读 `Keyboard.current.escapeKey` / `Mouse.current.position` 改为每帧轮询 `cancelAction.WasPressedThisFrame()` 与 `pointerAction.ReadValue<Vector2>()`（保持轮询而非回调，避免引入一套订阅生命周期）；无指针设备的判定下沉为宿主的 `InputManager.HasPointer`（`Mouse.current != null`），语义与改前一致。
    - **顺带修正**：`BackpackGridUI` 关闭态提示原先写死 `"TAB   /   打开背包"`（实际绑定是 B 键），改为 `OpenKeyLabel`——`openKeyHint` 留空时取开关动作的实际绑定显示名（`GetBindingDisplayString()`），不再与输入资产漂移。
    - **场景**：`New Scene.unity` 新增根物体 `InputManager`（挂 `InputManager` 组件），并删除 `BackpackGridUI` 上失效的 `backpackActions` 序列化行（该字段已从 C# 移除，历史上是唯一一处输入资产引用）。
    - **未改**：Mirror 协议、容器 / 宿主判定、事件总线与 `UiChannels` 契约；权威模型（UI 只发 `PushClick(int)` / `Toggle()` 意图）不变。

## 三、Inspector 手搭接线清单

### 1) 窗口（M5 既有）
`BackpackGridUI`（挂窗口根，CanvasGroup 由脚本自动补）：
- `slotPrefab` / `slots` / `slotLayer` / `itemLayer` / `cursorLayer`（可留空自动创建）
- `initialColumns` / `initialRows` 只是未绑定数据源前的占位尺寸；绑定后（以及每次打开）网格都按数据源的 `ConfiguredColumns` / `ConfiguredRows` 自动重建，无需手工对齐
- `hudHint` / `overflowText` / `uiFont`
- **新增** `interaction` → 指向本窗口的 `BackpackInteractionController`
- `openKeyHint` 只影响关闭态提示文案，留空时自动取开关键的实际绑定显示名；**不再有输入资产字段**（开关与左右键一律来自场景里的 `InputManager`）

### 2) 交互控制层
`BackpackInteractionController`（建议与窗口同物体，或任意常驻物体）：
- `grid` → 窗口主控
- `description` → 描述面板
- `popup` → 右键弹窗

### 3) 右键弹窗（已下线，无需接线）
`BackpackInteractionController` 上的 `popup` 字段已删除，右键不再打开该面板；`BackpackItemPopupView` 组件若仍挂在场景里，其 `Awake` 会自行收起面板且无 `Update`，留着不会有副作用。如需物理删除（含 `.meta` 与场景节点）另行处理。原接线字段（备用）：
面板根（背景 Image，建议 `VerticalLayoutGroup` + `ContentSizeFitter`）挂 `BackpackItemPopupView`：
- `boundary` → 画布根（**pivot 必须是 (0,0)**）
- `panelRoot` → 面板根自身或子节点
- `headerText` / `countValueText` / `countHintText`
- `decrementButton`（−）/ `incrementButton`（+）/ `splitButton`（拆分）/ `dropButton`（丢弃）/ `consumeButton`（消耗）
- `pointerOffset`（默认 12,12）、`fallbackSize`

### 4) 描述面板（自建节点）
面板根（背景 Image，`raycastTarget = true`）挂 `BackpackItemDescriptionPanel`：
- `boundary` → 画布根（pivot (0,0)）
- `panelRoot` / `headerText`
- `rowContainer` → 行容器（建议 `VerticalLayoutGroup`）
- `rowPrefab` → 满足以下约定的预制体：
  - 根节点：可选 `Button`（有则可点击展开该行）
  - 子节点：**第一个 `TMP_Text` = 标签，第二个 `TMP_Text` = 数值**
  - 建议行根挂 `LayoutElement`（minHeight = preferredHeight ≈ 20）保证行高稳定
- `pointerOffset`（默认 16,16）、`fallbackSize`

### 5) 输入宿主
`InputManager`（挂一个根物体，与窗口 / 交互层同场景即可；组件本身无序列化字段，挂上就生效）：
- 脚本位于 `Assets/Scripts/Input/InputManager.cs`（`RPG4.Input` 程序集），**没有可配项**：`Awake` 建单例、`DontDestroyOnLoad` 常驻，并独占启用 `backpack` 映射
- 输入资产仍是 `Assets/input/InputActions.inputactions`（`backpack` 映射：`BackPackUI` = B、`leftButton`、`rightButton`、`cancel` = ESC、`pointerPosition` = 鼠标坐标）；改键改这个资产，生成的包装类会重新落到 `Assets/Scripts/Input/InputActions.cs`
- 场景里漏挂时：日志出现「场景里没有 InputManager，背包收不到开关与点击。」，背包界面照常显示但无按键与鼠标响应

> 层级顺序：格子层 → 物品层 → 携带预览层（`cursorLayer`）→ 弹窗 / 描述面板。弹窗与描述面板在显示时会自己 `SetAsLastSibling`，但仍建议摆在最后。

## 四、人工验收（对应蓝本 T10）

1. Host + Client 各开一个实例，开关键（输入动作 `backpack/BackPackUI`，默认绑定 B，由场景里的 `InputManager` 常驻启用、`BackpackGridUI` 订阅后转发到主控）打开背包（关闭态查看 HUD 提示与溢出栏；提示里的按键名应与实际绑定一致）。
2. **悬停**：空手悬停物品 → 物品框描边变亮；拾起后悬停空格 = 绿、悬停异类单个物品 = 黄、被多个物品挡路或越界 = 红。
3. **拾起 / 放置**：左键点物品 → 该框从网格消失、半透明预览跟随光标；左键点空格 → 落位；位置只在本机生效（另一客户端位置不变，符合修正项 B）。
4. **堆叠三分支**（同类且双方可堆叠）：目标已满且源未满 → 数量互换；目标空位 ≥ 源数量 → 全部并入（源物品消失）；目标空位 < 源数量 → 部分填充（源剩余数量保留）。三者都提交服务端复核。
5. **异类换位**：拖不住的两件异类型物品点击后位置互换（仅本机）。
6. **右键拆 1 个**：右键点可堆叠且数量 > 1 的物品 → 源物品留在原格、显示数量 −1（如 10 → 9），鼠标上的半透明预览显示 ×1；此步不产生任何网络请求（日志为「右键拆出 1 个」，库存数据未变）。
7. **累加到取完**：指针保持在**同一源物品**上连续右键 → 取 2、3 … 直到取满（源显示数量递减至 0 后该物品从网格消失，预览 ×堆叠数）；鼠标移到别处右键**无操作**；ESC 取消 → 源显示数量与物品原样恢复。
8. **右键落下**：① 落到空格 → 源堆叠 −N，新实例落在**玩家点击的那一格**（服务端先放在它算出的空格，回传后本机认领并覆盖位置；主机端同帧完成，纯客户端有 1 个往返的轻微跳位）；② 落到同类堆叠且有余量 → 目标 +N、源 −N（余量不足填满则按 `room` 部分填充、结余留在源堆叠）；③ 目标已满 / 异类 / 被多个物品挡路 / 越界 → 这 N 个退回源堆叠（零数据写入）；④ 落回源物品自身 → 放回取消。
9. **取消（整件携带）**：左键拾起的整件携带仍可用右键或 ESC 取消，物品回到原格；右键拆分的部分携带只认 ESC。
10. **描述面板**：悬停 0.45s 出现；行可点击展开（数值从 `…` 变为实际值）；切换悬停目标会重新计时。
11. **异常路径**：关窗（开关键）→ 携带态与预览清理；携带中客户端收到复制更新（物品被移除）→ 自动放回并记 Warn。
12. **抓取格跟随**（承第 3 条）：点 2×3 大剑的非中心格 → 拾起瞬间预览不跳位，被点格始终贴住光标；落位后物品上左格 = 落点格 − 抓取偏移（点左上格落位时该格即上左格）。
13. **贴边外伸**：抓着非末列 / 非末行格把物品移到边缘 → 网格内的占格部分显示阻塞红、点击不落位；被点格仍严格在光标下（不夹取、不自动内缩）。
14. **网格外跟随**：指针移出网格（或落点越界）→ 预览自由跟随，被点格中心仍对准光标，出入网格不跳位。
15. **右键拆分异常路径**：容器没有能容纳拆分结果的空白区域时拆分被拒 → 0.5s 内未回传即放弃认领并记 Warn，源物品显示数量在 1s 兜底后还原为库存真值（物品不会凭空消失）。
