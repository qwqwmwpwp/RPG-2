## 2. 逐类型字段映射

### 2.1 `GridCoord`（网格坐标）

| 源 | Unity | 说明 |
|---|---|---|
| `FIntPoint` | `int X` / `int Y` | 单位是**格**，原点左上，X 向右、Y 向下 |
| — | `IsValid` | 两轴均非负；`Invalid` 为 `(-1, -1)` |
| — | `+` / `-` / `==` / `!=` / `Equals` / `GetHashCode` | 值语义，可直接做字典键 |
| — | `ToVector2Int()` / `FromVector2Int()` | 仅在与 UI / uGUI 交界处转换 |

- **不做 Index↔Position 换算**：换算统一由 F4 的 Utils 提供，防止出现两套口径。
- 亦复用为**尺寸**语义（源系统同样用 `FIntPoint` 承载物品占位宽高，如 Grid Fragment 的 `GridSize`）。

### 2.2 `TileQuadrant`（象限）

| 成员 | 值 | 语义 |
|---|---|---|
| `TopLeft` | 0 | 格内左上象限 |
| `TopRight` | 1 | 格内右上象限 |
| `BottomLeft` | 2 | 格内左下象限 |
| `BottomRight` | 3 | 格内右下象限 |
| `None` | 4 | 未命中任何格 |

**数值与顺序刻意与源系统一致**，硬断言 `0..4`，防止序列化 / 网络语义漂移。
用途：多格物品「上左索引」相对悬停索引的偏移方向（M6 顺序 1）。

### 2.3 `TileParams`（瓦片参数）

| 源 | Unity | 空态 |
|---|---|---|
| `TileCoordinats` | `TileCoordinates`（`GridCoord`） | `GridCoord.Invalid` |
| `TileIndex` | `TileIndex`（`int`） | `NoIndex` = `-1` |
| `TileQuadrant` | `Quadrant`（`TileQuadrant`） | `TileQuadrant.None` |

- 附带 `Empty` / `Reset()` / `IsValid`，服务**每帧覆盖写**的缓存复用路径。
- 附带 `==` / `!=` / `Equals`：对应源工程 `FMIS_TileParameters` 的 inline `operator==`（三字段全比较），
  供「本帧参数 vs 上帧参数」（源工程字段 `LastTileParameters` / `TileParameters`）做变更判定。
- 生命周期：**Tick 驱动**（旁注 E），鼠标离开网格调用 `Reset()`。

### 2.4 `SlotAvailability`（槽位可用性）

| 源 | Unity | 说明 |
|---|---|---|
| `Index` | `Index` | 被占用槽位记录**占用物品的上左索引**，空槽位记录自身索引 |
| `AmountToFill` | `AmountToFill` | **仅可堆叠物品记数** = `min(剩余待填, 该格最大堆叠 − 该格现有堆叠)`；不可堆叠时**恒为 0** |
| `bItemAtIndex` | `HasItemAtIndex` | 该索引上是否已有物品（交换判据） |

- 源工程取索引原文：`HasValidItem(GridSlot) ? GridSlot->GetUpperLeftIndex() : GridSlot->GetIndex()`；
  故同一物品占用的多格明细会**重复出现同一个上左索引**，下游按索引归并（勿当成「每格唯一」）。
- 附 `Invalid` / `IsValid` / `HasRoom`（Unity 侧附加便利成员，源工程无，不影响契约语义）。

### 2.5 `SlotAvailabilityResult<TItem>`（槽位可用性结果）

| 源 | Unity | 说明 |
|---|---|---|
| `TWeakObjectPtr<InventoryItem> Item` | `TItem Item` | **被查询 / 待放入的物品**（源注释原文「被查询的物品」），由调用方赋值 |
| `TotalRoomToFill` | `TotalRoomToFill` | 各槽位 `AmountToFill` 之和；不可堆叠物品每格计 1，故此时等于「可放置的槽位数」 |
| `Remainder` | `Remainder` | 补入后仍放不下的剩余量（部分填充分支回传） |
| `bStackable` | `IsStackable` | 被查询物品是否可堆叠 |
| `TArray<FIC_SlotAvailability>` | `IReadOnlyList<SlotAvailability> SlotAvailabilities` | 逐槽位明细 |

- 泛型化原因：Core **不得**反向引用 Items 程序集（与修正项 H「数据层不得持有 UI 引用」同源约束）。M1 落地后统一书写 `SlotAvailabilityResult<InventoryItem>`。
- **是 class 不是 struct**：源系统在网格循环中**增量填充**（累加总量、逐条追加），struct 副本会丢累加；配 `Add()` / `Clear()` 复用实例，避免 M6 逐帧查询产生 GC。
- `HasRoom` 只回答「能放进一部分或全部」。
- 源工程赋值路径对照：`PutHoverItemBack` 显式写 `Result.Item = HoverItem->GetInventoryItem()`；
  `AddItem`（拾取新物）**不赋值**。因此 `AddStacks` 里「明细为空且 `Item` 有效」的合并分支只服务于**放回悬停物**场景，
  M2 迁移时不要假设 `HasRoomForItem` 会回填 Item。

### 2.6 `SpaceQueryResult`（空间查询结果）

| 源 | Unity | 说明 |
|---|---|---|
| `bHasSpace` | `HasSpace` | 落点是否完全空置：扫描范围内**只要有一格被占**即 false |
| `TWeakObjectPtr<InventoryItem> ValidItem` | `TItem ValidItem` | 挡路的**单个**可交换物品；仅当被占格同属一个上左索引时才有值 |
| `int32 UpperLeftIndex` | `UpperLeftIndex` | 该候选物的**上左格索引**（不是悬停落点索引） |

- `CanSwap` 是**派生属性**（`ValidItem != null`）：源工程由 `OccupiedUpperLeftIndices.Num() == 1` 判定，**不存独立字段**。
- 源工程**没有** `SwapDimensions`：交换后重算占位所需尺寸在使用点另取该物品的 Grid Fragment
  （`ChangeHoverType(UpperLeftIndex, GridFragment->GetGridSize(), GrayedOut)`）。
- M6 顺序 2 三分流：`HasSpace` → 高亮；否则 `CanSwap` → 置灰；否则 → 无高亮（**多个物品挡路**）。
- 空态 `Empty`：无空间、无候选、索引 `-1`（= 源工程默认构造）。

## 3. 「落点索引 / 上左索引」归属对账（F3 旁注）

F3 旁注要求后续交换 / 拆分 / 填充 / 消耗四条分支依赖的五项数据，逐项落在：

| 判据 | 承载位置 | 写入方 | 读取方 |
|---|---|---|---|
| 落点索引 | `TileParams.TileIndex` | M6 顺序 1（每帧，鼠标→格子→索引） | M6 顺序 2~8 全部分支 |
| 上左索引（悬停物） | **M6 顺序 1 的本地缓存**：`TileParams.TileCoordinates` + `TileQuadrant` + 悬停物占位尺寸推导（RPG_4 改为「被点击格 − 物品上左格」的抓取偏移，见本节末注记） | M6 | M6 高亮 / 占位 / 交换判定 |
| 上左索引（挡路物） | `SpaceQueryResult<TItem>.UpperLeftIndex` | M2 / M6 空间查询 | M6 顺序 2 置灰高亮 |
| 总可填量 | `SlotAvailabilityResult.TotalRoomToFill` | M2 空间查询 | M6 顺序 5；M3 堆叠命令 |
| 剩余量 | `SlotAvailabilityResult.Remainder` | M2 空间查询 | M6 顺序 5；M3 部分堆叠回传 |
| 可堆叠标志 | `SlotAvailabilityResult.IsStackable` | M2 空间查询（源自 Stackable Fragment） | M6 顺序 5 优先级链首判 |

- 悬停物的上左索引是**每帧派生量**（随象限变化），刻意不进契约：源工程同口径由
  `CalculateStartingCoordinate(Coordinate, Dimensions, Quadrant)` 计算，公式为
  `起始 = 坐标 − ⌊尺寸 / 2⌋（尺寸为偶数时按象限再 +1）`，`Quadrant == None` 时返回 `(-1, -1)`（与 `GridCoord.Invalid` 一致）；
  该函数属 **M6 顺序 1**，F3 只提供其输入契约。
  **RPG_4 偏离（2026-10-06）**：M6 落地时未沿用该象限公式——拾起时记录「被点击格 − 物品上左格」的抓取偏移，此后落点 = 悬停格 − 偏移（`BackpackGridUI.GetUpperLeftIndex(int, Vector2Int)`，换算走 `GridUtils`）；`TileQuadrant` 仍由 `TryResolveTile` 判定、`TileParams.IsValid` 仍依赖它，但不再参与上左索引推导。详见《里程碑/M6_点击拾取与堆叠操作.md》§二第 11 条。
- `TileParams.TileIndex` 与 `SlotAvailability.Index`、`SpaceQueryResult<TItem>.UpperLeftIndex` **同为线性索引口径**（行优先），三者可交叉比对。
  注意三者语义并不等价：`TileIndex` 是鼠标命中的那一格，另两者是「物品占位锚格」。

## 4. Unity 侧决策与偏差记录

| # | 决策 | 理由 |
|---|---|---|
| 1 | 不直接用 `Vector2Int`，自建 `GridCoord` | 语义隔离（格 ≠ 像素）、带 `IsValid`、可 `[SerializeField]`、避免误用浮点 API |
| 2 | `SlotAvailabilityResult<TItem>` 泛型化 | Core 零业务依赖；同时保住 `Item` 字段，不丢源系统语义 |
| 3 | 结果类型用 class + `Clear()` | 增量填充语义 + 复用不产生逐帧 GC |
| 4 | `bStackable` / `bHasSpace` → `IsStackable` / `HasSpace` | 命名规范禁止 `b` 前缀（不沿用 UE 命名） |
| 5 | `TileCoordinats` → `TileCoordinates` | 源系统拼写错误不予继承 |
| 6 | 四结构用 `[SerializeField]` 私有字段 + 大驼峰属性 | 与项目既有风格一致，且允许 M5 在 Inspector 配置槽位坐标 / 尺寸默认值 |
| 7 | 未引入任何 Mirror 标注 | 修正项 B：网格位置不参与复制，这些契约不进同步通道 |
| 8 | 不移植 `Selected` 等零调用成员 | 修正项 J：段内死代码不移植 |
| 9 | 补 `TileParams` 的 `==` / `!=` / `Equals` / `GetHashCode` | 源工程定义了 inline `operator==`（三字段全比较），用于「本帧 vs 上帧」判定，缺则退化 |
| 10 | `SpaceQueryResult` 按源码改为 `HasSpace` + `ValidItem` + `UpperLeftIndex`，去掉臆造的 `CanSwap` 字段 | **2026-09-20 源码对照修正**：蓝本工作区 `ItemCore设计文档.md` 5.6 记载的 `bCanSwap / SwapIndex / SwapDimensions` 在源工程中**并不存在**，一律以源头文件为准 |

## 5. 对后续阶段的硬约束

1. **F4**：Index↔Position 换算只接受 `GridCoord`，不得另立第二套坐标类型；换签名建议 `GetIndexFromPosition(GridCoord coord, int columns)` / `GetPositionFromIndex(int index, int columns)`。
2. **M2**：空间查询返回 `SlotAvailabilityResult<TItem>`；填充顺序固定为「遍历槽位 → `Add` → 累加 `TotalRoomToFill` / `Remainder`」。查询本身不得依赖 UI（修正项 H）。
3. **M6**：`TileParams` 是**唯一**每帧缓存；顺序 2~8 只读不重算（旁注 E / M6 旁注）。
4. **UI / 表现层**：不得改写契约语义（例如把 `TileIndex` 当像素坐标、把 `UpperLeftIndex` 当成悬停落点索引、或把 `GridCoord` 当世界尺寸）。

## 7. 源工程逐字段对照结论（2026-09-20）

对照基准（只读，不改动，位于蓝本工程外部）：
`InventorySystems-main-master/Plugins/MultiplayerInventory/Source/MultiplayerInventory/Public/Types/MIS_GridTypes.h` 及其 `.cpp`、
`Plugins/ItemCore/.../IC_GridTypes.h`、`Plugins/Inventory/.../Inv_GridTypes.h`，
以及调用点 `MIS_InventoryGrid.cpp`。

| 项 | 结论 |
|---|---|
| 象限枚举 | 成员与序**完全一致**（`TopLeft, TopRight, BottomLeft, BottomRight, None`），底层 `uint8`；Unity 用 `int` 默认值 `=None` |
| 瓦片参数 | 三字段一致；源有 inline `operator==` → **本次已补** `==` / `!=` / `Equals` / `GetHashCode` |
| 槽位可用性 | 三字段一致；`Index` / `AmountToFill` 语义按源码**已校正**（见 2.4）——不可堆叠物品 `AmountToFill` 恒为 `0`，放置量不进该字段 |
| 槽位可用性结果 | 四字段一致；`Item` 语义按源码调用点**已校正**（见 2.5）——是「被查询 / 待放入的物品」，由调用方赋值 |
| 空间查询结果 | **字段不符 → 已改**（偏差 #10）：源为 `bHasSpace` + `ValidItem` + `UpperLeftIndex` |
| 索引换算 | 源在 `UInventoryGridFunctionLibrary` 内：`GetIndexFromPosition = X + Y * Columns`、`GetPositionFromIndex = (Index % Columns, Index / Columns)`；**F4 原样照搬此公式**，不引入第二种口径 |
| 二维遍历 | 源 `ForEach2D(Dimensions, 回调 (int Index, FIntPoint Position))`：以**尺寸**为界、按行优先出索引与坐标 → F4 的 `ForEach2D` 按此签名落地，行优先顺序与 `SlotAvailabilityResult` 明细顺序对齐 |
| 死代码 | 源工程同样保留了 `EMIS_GridSlotState::Selected`、`GetVisibleCursorWidget` 等零调用成员 → **不移植**（偏差 #8，源工程历史包袱不是移植理由） |
