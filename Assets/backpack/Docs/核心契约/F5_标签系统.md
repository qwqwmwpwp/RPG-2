## 2. 匹配语义（两类，不可混用）

### 2.1 精确匹配 `MatchesTagExact`

| 源 | Unity | 判定 |
|---|---|---|
| `A.MatchesTagExact(B)` | `a.MatchesTagExact(b)` | 整串序数相等，**不做**层级展开 |
| 源实现（GMP 同形文档）：`if (!TagToCheck.IsValid()) return false; return TagName == TagToCheck.TagName;` | `if (IsEmpty \|\| other.IsEmpty) return false; return string.Equals(name, other.Name, StringComparison.Ordinal);` | 任一侧为空 → `false`；否则逐字符比较 |

### 2.2 层级匹配 `MatchesTag`（仅装备可装判定使用）

源文档（GMP `MessageTagContainer.h:106-113`，UE 同文）：

```
Determine if this tag matches TagToCheck, expanding our parent tags
"A.1".MatchesTag("A") will return True, "A".MatchesTag("A.1") will return False
If TagToCheck is not Valid it will always return False
```

- **调用方向**：`接收者（更具体的子标签）.MatchesTag(参数（更泛的父标签）)`。
- 例：`GameItems.Equipment.Weapons.Sword`.MatchesTag(`GameItems.Equipment.Weapons`) → `true`。
- `parent` 为空 / 自身为空 → `false`（**安全失败方向**：空槽位标签不接纳任何物品）。
- 实现为**零分配**路径：长度短路 → 分隔符位校验 → `string.CompareOrdinal` 定长前缀比较。

### 2.3 空标签与 C# 相等契约

| 场景 | 判定 | 理由 |
|---|---|---|
| `Empty.MatchesTagExact(Empty)` | `false` | 源文档：`TagToCheck` 无效恒为 `false` |
| `Empty.MatchesTag(x)` / `x.MatchesTag(Empty)` | `false` | 同上 |
| `Empty == Empty`（`Equals` / `operator ==`） | `true` | C# 相等契约必须自反；`HashSet` / 字典 / 列表去重依赖它 |
| `tag.IsValid` | 非空 **且** 分段合法（`IsWellFormed`） | 与 `IsEmpty` 区分：脏数据可能非空但不合法 |

> 注：匹配 API 与相等运算符**有意不同口径**——前者是玩法规则（对齐源），后者是集合语义（对齐 C#）。文档与 XML 注释均写明，避免后继阶段误用。

### 4.3 `TagRegistry`（ScriptableObject）

| 成员 | 语义 |
|---|---|
| `Current`（静态） | 显式注入优先 → `Resources.Load("TagRegistry")` 兜底 → `CreateRuntimeDefault()` 空表（不抛异常），完全复刻 `BackpackLog.Settings` 链路 |
| `AllTags` | 已登记标签（资产填写顺序），供抽屉与校验使用 |
| `Contains(tag / name)` | 序数 `HashSet` 查询，O(1)；空标签恒 `false` |
| `GetChildren(parent)` | 直接子节点枚举；`parent` 为空 → 全部一级分段；**父节点无需登记**，由分段推导并去重 |
| `Validate()` | 注册表自身：空条目 / 重复登记 / 格式非法 |
| `InvalidateCache()` | 索引重建并递增 `Version`（`OnValidate` 已自动触发） |
| `TagValidationIssue` | `Context`（`TagRegistry[3]` 或资产路径）+ `Message`，`ToString()` 直接可读 |

- 判定链：`Contains` 只查注册表，**不改变**任何标签的匹配结果；注册表缺席时匹配照常工作。
- 「父节点不登记」是硬约定：注册表内容 = 叶子标签全集，`GetChildren` 允许返回**未登记**的中间节点（菜单需要）。

## 7. 对后续阶段的硬约束

1. **M1/M6/M7**：标签一律用 `BackpackTag`（`Fragment` / `Manifest` / 装备槽 / 装备 Actor / 事件载荷），**禁止**裸字符串比较（`"GameItems.Equipment.Weapons.Sword" == x`）代替匹配 API。
2. **M6（堆叠）**：同类型判定必须用 `MatchesTagExact` —— 层级匹配会把「剑」与「斧」都归入「武器」而误判可堆叠。
3. **M7（装备）**：可装判定用 `MatchesTag`（子标签对父标签），槽位内二次校验（修正项 G）用 `MatchesTagExact`；两者顺序不可互换。
4. **M1（Fragment 查找）**：`GetFragmentOfTypeWithTag<T>` 的标签比较用 `MatchesTagExact`；不带标签的 `GetFragmentOfType<T>` 继续按类型查找。
5. **M5（Composite 同化）**：Composite 的 `FragmentTag` 与 Fragment 的 `FragmentTag` 必须**精确相等**才展开控件树（源 `MatchesWidgetTag`）；控件折叠/展开不得用层级匹配。
6. **新增标签**：先加进 `Data/TagRegistry.asset`，再在常量清单补常量（如有代码调用点），最后跑 `Tools/Backpack/标签校验/全工程标签校验` 确认为零问题（该校验入口随 Editor 轮落地）。
7. **序列化字段名**：`BackpackTag.name` 是抽屉的硬依赖，**禁止改名**；新增持标签的资产字段无需任何额外注册。
8. **注册表不参与匹配**：任何判定都不得以「注册表里有没有」为前提；`Contains` 仅用于提示与校验。

## 9. 常用写法（供 M 阶段直接抄）

```csharp
// ① 精确匹配：同类型堆叠（M6）/ 装备槽内二次校验（M7，修正项 G）
bool sameType = hoverItemType.MatchesTagExact(clickedItemType);

// ② Fragment 按标签查找（M1）
GridFragment grid = manifest.GetFragmentOfTypeWithTag<GridFragment>(FragmentTags.GridFragment);

// ③ 层级匹配：物品的具体类型 vs 槽位的泛类型（M7 可装判定，源唯一层级匹配点）
bool canEquip = equipmentFragment.EquipmentType.MatchesTag(slot.EquipmentType);

// ④ 注册表查询：只用于提示 / 校验，不参与匹配结果
if (!TagRegistry.Current.Contains(itemType))
{
    BackpackLog.Warn(LogModule.Items, () => $"未登记的物品类型标签：{itemType}");
}

// ⑤ 层级推导：取某节点的直接子类（下拉 / 分类树）
IReadOnlyList<BackpackTag> categories = TagRegistry.Current.GetChildren(new BackpackTag("GameItems.Equipment"));

// ⑥ 格式校验（Editor 或导入期）
if (!BackpackTag.IsWellFormed(rawName, out string reason))
{
    // 记录 reason，见 TagRegistryValidator.Evaluate
}

// ⑦ 事件载荷（F6）：BackpackTag 是普通 struct，可直接作为消息参数投递，无需字符串转换
EventBus.Global.Publish(UiChannels.EquippedGridSlotClicked, this, equippedGridSlot, equipmentTypeTag);
```
