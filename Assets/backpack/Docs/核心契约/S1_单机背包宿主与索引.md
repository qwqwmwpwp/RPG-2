# S1 · 单机背包宿主与索引

> 范围：**数据层宿主**。给玩家 / 箱子物体提供各自独立的背包数据与查找入口；单机宿主与联机宿主在 2026-10-06 抽取出共享核心 `InventoryHostCore`（见 §2.5，本轮补记），双方遵循同一「UI 发意图 → 主端判定执行 / 转发 → 状态回传」关系。
> 落盘：`Assets/backpack/Scripts/Runtime/`（宿主与索引）+ `Assets/backpack/Scripts/Inventory/InventoryHostCore.cs`（共享核心）；程序集 `RPG4.Backpack.Runtime`（`references = Core / Items / Inventory`）与 `RPG4.Backpack.Inventory`（核心所在程序集，零 asmdef 改动）。
> 复用：M2 `InventoryContainer`（原子提交 · 失败零变更）、M1 `RuntimeItem` / `ItemManifest` / `ItemManifestCatalog` / `ItemIdGenerator` / `RuntimeItemSnapshotCodec`、F4 `BackpackLog`、F6 `EventBus`。

## 2. 组件契约（BackpackInventory）

### 2.1 Inspector

| 字段 | 默认 | 说明 |
|---|---|---|
| `rows` / `columns` | 6 / 8 | 容器尺寸；非正或乘积 > 65536 → 回退 6×8 并记 Warn（核心统一口径） |
| `isLocalPlayerInventory` | true | 登记为 `BackpackRegistry.Primary`；箱子等取消勾选 |
| `catalog` | 空 | 拆分按类型取模板必需；留空时拆分被拒并记 Warn |
| `fillCatalogOnStart` | false | 测试用：Start 时把目录模板各填一份（仅调试） |

### 2.2 只读查询（视图契约 + 直连容器）

| 成员 | 语义 |
|---|---|
| `Container` | 权威容器（核心持有），可直接做落点 / 容量等富查询 |
| `ConfiguredRows` / `ConfiguredColumns` | 面板配置行列（不代表容器实际尺寸；UI 绑定与每次打开时按它重建网格） |
| `IsLocalPlayerInventory` | 是否登记为本地玩家背包 |
| `EventSource` | 事件管线键：恒为权威容器实例（订阅 `Inv.*` 通知与发布 `Cmd.*` 意图共用） |
| `Catalog` | 物品目录（可运行时注入，写入时同步给核心） |
| `CopyItems(List<RuntimeItem>)` | 按 ItemId 升序确定性输出（先清空目标）；容器未创建时清空并返回 |

### 2.3 本地权威写入（转发核心，失败零变更）

| 成员 | 语义 |
|---|---|
| `TryAddItem(ItemManifest, stackCount, out RuntimeItem, out error)` | 发新标识 + 模板建实例 + 整批收纳；装不下整体失败 |
| `TrySplitStack(RuntimeItem, splitCount, out ItemId, out error)` | 拆分出独立实例（流程见 §4.2） |

> 其余写入（放置 / 移除 / 设置堆叠数 / 堆叠合并）直连 `Container.TryXxx`，或经 `Cmd.*` 意图由共享核心处理。

### 2.4 意图模型（单机与联机同一关系）

- UI 只发布 `Cmd.SetStackCount` / `Cmd.RemoveItem` / `Cmd.SplitStack`（source = `EventSource`），宿主把意图交给核心处理。
- 核心按 `IsAuthority` 判定「自己是否为主端」：单机 / 主机 / 服务端为主端 → 直接复核执行；纯客户端非主端 → 调用宿主注入的 `Forward*` 转发（联机 = Mirror `[Command]`）。
- 命令不保证成功；结果一律由容器广播 `Inv.Changed` 回传（失败只记日志）。
- 订阅生命周期：`OnEnable` → `core.SubscribeCommands(Container)`，`OnDisable` → 退订（`EventBus` 弱引用 + 显式 `Dispose` 双保险）。

### 2.5 共享核心契约（InventoryHostCore）

| 成员 | 语义 |
|---|---|
| 构造 `(LogModule, ownerName)` | 非权威端（纯客户端）：不创建容器，只承载意图订阅与转发 |
| 构造 `(rows, columns, LogModule, ownerName)` | 权威端：创建容器；尺寸非法回退 6×8 并记 Warn |
| `Container` | 权威容器；纯客户端为 null（核心内各操作自带未初始化守卫） |
| `Catalog` | 新增 / 拆分按类型取模板的目录 |
| `IdGeneratorProvider` | 标识生成器提供者；留空自建（单机每包一份），联机注入服务端生成器 |
| `IsAuthority` | 自己是否为主端；留空恒 true |
| `ForwardSetStackCount` / `ForwardRemoveItem` / `ForwardSplitStack` | 非权威端转发委托 |
| `CommitConfirm` | 权威提交后的确认钩子（联机 = `SyncEntries` 投影）；返回 false 触发核心回滚 + 补偿确认 |
| `SubscribeCommands(object sourceKey)` / `UnsubscribeCommands()` | 订阅 / 退订三个 `Cmd.*` 频道（幂等；sourceKey：权威端 = 容器，纯客户端 = 宿主自身） |
| `TryGetItem` | 容器直查（线性扫描，仅低频路径） |
| `TryAddItem` / `TrySetStackCount` / `TryRemoveItem` / `TrySplitStack`（`ItemId` 与 `RuntimeItem` 两个重载） | 权威操作；任一步失败零变更，确认失败按各操作口径回滚 |

**日志口径**：核心判定的拒绝写一条 Warn（`{ownerName}：{操作} 被拒绝：{原因}`）；容器判定的拒绝由容器自记；意图命令骨架与联机 `Cmd` 层不重复记录。

## 3. 索引语义（BackpackRegistry）

1. `Primary` / `TryGetPrimary(out)`：本地玩家背包；组件 OnEnable 自动登记，`isLocalPlayerInventory = true` 且**先注册者胜**（重复者记 Warn）。
2. `TryGet(GameObject owner, out)`：先取同物体组件，再取子物体组件（含未激活）。
3. `SetPrimary(BackpackInventory)`：显式覆盖 / 传 null 清除；覆盖已存在的不同实例时记 Info。
4. 组件 OnDisable / 销毁时自动注销；被注销者若为 Primary 则置空。
5. 静态状态在 `SubsystemRegistration` 复位（关闭 Domain Reload 时防上一局残留）。

## 4. 关键规则

### 4.1 变更通知

- 所有成功写入经 `InventoryContainer.BumpRevision()` 广播 `Inv.Changed`（source = 容器实例）；另有细分广播 `Inv.ItemAdded` / `Inv.ItemRemoved` / `Inv.StackChanged`（当前无订阅者，M7 起按需接入）。
- 表现层收到后置脏、帧末合并刷新一次（`BackpackGridUI.LateUpdate`）；单机宿主不额外发通知。
- `RuntimeItem.StackCount` 的**正常提交**必须走 `Container.TrySetStackCount`（推进 Revision 并广播 `Inv.StackChanged`）；直接 `SetStackCount` 仅用于失败回滚（联机投影失败撤销）。

### 4.2 拆分流程（核心 `TrySplitStack`，任一步失败整体零变更）

1. 定位源物品 → 可堆叠校验 → 数量边界 `1 .. 源堆叠数 - 1`。
2. 目录按 `ItemType` 取模板 → `RuntimeItemSnapshotCodec.TryCapture` 抓源快照。
3. 发新标识 → 用「源快照 + 拆分数量」恢复新实例（数值原样继承、不重新随机）。
4. 行优先 `QuerySpace` 扫首个能完整容纳的空白区域；无区域即拒绝。
5. 提交：源堆叠数扣减 + 新实例落位；放置失败回滚源堆叠数；确认失败（联机投影）回滚新实例与源并补偿确认。

### 4.3 尺寸回退

`rows / columns` 非正或 `rows × columns > 65536` → 回退 `6 × 8` 并记 Warn（核心统一校验，单机与联机同口径）。

## 6. 手搭与冒烟

### 6.1 单机

1. 场景新建空物体（或玩家 / 箱子），挂 `BackpackInventory`；玩家物体保持 `isLocalPlayerInventory = true`，箱子取消勾选。
2. 给组件 `catalog` 指到 `Data/Items/` 的 `ItemManifestCatalog` 资产（拆分验证必需）。
3. 组件右键菜单依次核对：`测试/从目录填入物品` → `测试/拆分首个可堆叠物品` → `测试/打印背包内容` → `测试/清空背包`。
4. `BackpackRegistry.TryGetPrimary(out var bag)` 与 `BackpackRegistry.TryGet(chestGo, out var chestBag)` 命中各自容器。
5. 失败路径抽查：拆分数量越界 / 目录为空 / 背包塞满 → 返回 false + 原因，容器数量不变。

### 6.2 联机回归（共享核心改动后必查）

1. Host + Client 各开一实例；客户端拆分 / 堆叠 / 交换数量 → 服务端复核后两侧镜像一致。
2. **主机端堆叠刷新**（本次统一后的修复点）：主机上点「+ / −」调整堆叠数 → 主机界面立即刷新（容器广播 `Inv.Changed`）。
3. 纯客户端：意图只经 `Command` 上行，本地无容器；断网 / 非本人库存的请求被 `CanSendRequest` 拒绝并记 Warn。
4. 投影失败路径（模板未初始化）→ 新增 / 拆分 / 设堆叠数整体回滚，容器与镜像一致。

## 7. UI 接入（已由 M5 / M6 完成）

1. `IBackpackView`（`Scripts/Inventory/`）承载 `ConfiguredRows` / `ConfiguredColumns` / `EventSource` / `CopyItems`，单机与联机宿主各实现一份。
2. `BackpackGridUI.ResolveSource`：联机优先（`NetworkClient.localPlayer` 上的 `BackpackNetworkInventory`），未联机回退 `BackpackRegistry.TryGetPrimary`；0.25s 轮询 + 单绑定槽。
3. `BackpackInteractionController` 经 `Cmd.*` 发布意图（source = `EventSource`），订阅 `Inv.Changed` 置脏重绘。
