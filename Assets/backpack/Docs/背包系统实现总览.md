# 背包系统实现总览（RPG_4 · 2026-10-06）

> **现状快照**（代码为准）：改动前先在此定位板块，再进 `Docs/核心契约/` 对应文档。与代码冲突时以代码为准并回来修订本文件。

**四条主线**：① 一套内核（`InventoryHostCore`）两种宿主（单机 `BackpackInventory` / 联机 `BackpackNetworkInventory`，Mirror 服务端权威）；② 真相源只有 `cells[]` + `placements` 两份状态，堆叠数单一来源 `RuntimeItem.StackCount`；③ UI 只发 `Cmd.*` 意图，结果一律由 `Inv.Changed` 回传；④ 网络只同步数据、不同步网格位置。

---

## 1. 分层与程序集

依赖方向 `Core ← Items ← Inventory ← {Runtime, Equipment, Network} ← UI`（单向无环）。

| 程序集 | 依赖 | 职责 | 目录内容 |
|---|---|---|---|
| `RPG4.Backpack.Core` | — | 事件总线 · 标签 · 网格类型 · 日志 | `Events/` `Tags/` `Types/` `Utils/` |
| `RPG4.Backpack.Items` | Core | 片段 · 物品清单 · 运行时物品与快照 | `Runtime/` `Fragments/` `Manifest/` `BackpackItem.cs` |
| `RPG4.Backpack.Inventory` | Core Items | **库存真相源** · 共享宿主核心 · 视图接口 | `InventoryContainer` `InventoryHostCore` `InventoryPlacement` `IBackpackView` `Backpack(Data)` |
| `RPG4.Backpack.Runtime` | Core Items Inventory | 单机宿主 + 静态索引 | `BackpackInventory` `BackpackRegistry` |
| `RPG4.Backpack.Equipment` | Core Items Inventory | 装备（M7） | **空目录，仅 asmdef** |
| `RPG4.Backpack.Network` | Core Items Inventory **Mirror** | Mirror 基座 · 网络宿主 · 投影 | `BackpackNetworkManager` `BackpackNetworkPlayer` `Inventory/` |
| `RPG4.Backpack.UI` | 全部 + Mirror/UI/TMP/InputSystem | 网格主控 · 占位布局 · 物品框 · 交互 | 5 个脚本（`Grid/` `HUD/` 为空） |

其他目录：`Data/` = 7 个物品清单 `.asset` + 目录 + `LogSettings` + `TagRegistry`；`Tests/` = 5 个**空目录**；UI 是扇出最广的顶层，`Network` 是唯一持有 Mirror 依赖的业务程序集。

## 2. 数据模型

| 概念 | 类型 | 关键点 |
|---|---|---|
| 物品抽象面 / 运行时实例 | `BackpackItem` / `RuntimeItem` | 实例 = `ItemId` + 标签 + `List<ItemFragment>` + 可变 `stackCount`；可否堆叠由 `StackableFragment` 派生 |
| 模板 / 目录 | `ItemManifest` / `ItemManifestCatalog`（SO） | 创建 = 克隆模板 + 首次随机化；恢复 = 按快照还原**不重新随机化**；目录惰性字典，重复标签保留第一条 |
| 放置记录 | `InventoryPlacement`（readonly struct） | `Item` + `UpperLeftIndex`（行优先）+ **冻结的** `Dimensions`；`Invalid` = 空置格 |
| 容器（真相源） | `InventoryContainer` | 单一矩形网格，纯 C#（无 UI/Mono/网络）；`Revision` 供变更检测；上限 65536 格 |
| 宿主核心 | `InventoryHostCore` | 容器创建 · 意图分发 · 编排（新增/设堆叠/移除/拆分），单机联机共用 |
| 单机宿主 / 索引 | `BackpackInventory` / `BackpackRegistry` | 宿主只做「建核心 + 注册 + 测试辅助」不中转数据；`Primary` 先注册者胜，`TryGet` 同物体→子物体 |

- 尺寸取 `GridFragment.Width/Height`，缺失按 1×1；**放置时冻结进记录**，释放不回头查片段。
- `Backpack` / `BackpackData` 是一对**不可变只读映射**（逐格物品下标 + 冻结顺序集合），构造注入是唯一入口，无变更操作，与可变容器并存。

## 3. 空间查询与索引

| 问题 | API | 语义 |
|---|---|---|
| 单格读取 | `IsIndexOccupied` / `GetItemAt` / `GetUpperLeftIndexAt` | O(1)；物品→记录走 `placements` 字典 O(1) |
| 放得下吗 | `QuerySpace(startIndex, dimensions)` | 全空 → 可放；被挡且占格同属一个物品 → 交换候选；多物品挡路 → 空结果 |
| 放几个、剩多少 | `QueryAvailability` / `FillAvailability` | 行优先扫描 + 轮次戳跳区 + `Remainder` 归零提前退出；不可堆叠按每格 1 计 |
| 区域可堆叠 | `TryValidateRegion` | 上左格须正是区域起点 + 双方可堆叠 + `MatchesTagExact` + 未满堆 |

主线程单线程不加锁，热路径零 GC（轮次戳 + `ref struct`，无 LINQ/闭包），刻意不引空间树。**未实现旋转/朝向**（仅上左格 + 固定宽高正放）。

## 4. 数据流

**写路径全部原子（失败即零变更）**

| 操作 | 步骤 |
|---|---|
| 新增（全量吸收） | 发新 `ItemId` → 克隆+随机化 → 只读规划（先并堆叠、余量落首个空白区）→ 一次性提交；装不下整体失败 |
| 移除 | 释放占格 + 移出 `placements`；确认失败**不回滚** |
| 拆分（5 步） | 归属/可堆叠/边界 1..n-1 → 取模板 → 抓快照 → 新标识恢复 → 行优先找位；任一步失败零变更，确认失败回滚 |
| 设堆叠数 | 必须走 `TrySetStackCount`（推进 `Revision` + 广播）；直接 `SetStackCount` 仅限回滚 |

**频道（`Core/Events/EventChannels.cs`，键的唯一来源）**

| 频道 | 方向 | 语义 |
|---|---|---|
| `Inv.Item.Added` / `.ItemRemoved` / `.Stack.Changed` | 数据 → 表现 | 具体变更；`Stack.Changed` 载荷 `SlotAvailabilityResult` |
| `Inv.Changed` | 数据 → 表现 | 粗粒度脏信号，UI 置脏、帧末合并刷新一次 |
| `Cmd.Item.SetStackCount` / `.Remove` / `.Split` | UI → 数据 | 不保证成功；主端直接执行，非主端走 `Forward*` |
| `Ui.*` | UI 内部 | 以组件实例作 source，不经数据层 |

广播**只在成功提交路径**（查询不广播），source 恒为容器实例。联机由 `CommitConfirmHandler` 在提交后确认（= 投影同步），返回 false 触发回滚 + 补偿确认。

## 5. 网络同步（Mirror）

1. **服务端权威**：`OnStartServer` 建核心持容器；纯客户端**无容器**，只持只读镜像 + 转发 `Command`；Host 模式不建镜像避免双份物品。
2. **写方向单向**：客户端意图 → `[Command(requiresAuthority = true)]`（发送前 `CanSendRequest` 守卫）→ 服务端复核 → 容器原子改 → 投影差异 → 客户端镜像，**不允许反向写回**；`Revision` 未变则整段跳过。
3. **同步内容**：`SyncList<NetworkInventoryEntry>` 的 `itemId / itemType / stackCount / fragmentState`（public 实例字段供 Weaver）；**位置与 Unity 引用不同步**。
4. **编码**：`fragmentState` 由 `RuntimeItemSnapshotCodec` 定长二进制（`[version:1][count:2]` + 每节点 8 字节）；`StateEquals` 逐字节比，只在实际变化时下发。
5. **分工**：`BackpackNetworkInventory` = 宿主/Command 收口/投影上报；`InventoryNetworkProjection` = **纯投影逻辑（不依赖 Mirror/Unity，可独立单测）**；`NetworkInventoryEntry` = 元素 + `TryValidate` + 相等比较。
6. **裁剪状态**：M3-only 裁剪版，已剥离 M4 拾取 12 处、M8 钩子 4 个；M6 拆分已回填；装备/消耗分片未编入（回填行号见 `BackpackNetworkInventory.cs` 头部注释）。

## 6. UI 表现层

1. **绑定**：`ResolveSource` 优先本地玩家 `BackpackNetworkInventory`，未联机回退 `BackpackRegistry` 单机宿主——表现层只依赖 `IBackpackView`，换部署形态 UI 零改动；`BindInventory` 先 `SyncGridSize` 再订阅 `InvChannels.Changed`；`LateUpdate` 帧末合并刷新一次。
2. **重绘**（`BackpackGridUI.Refresh`）：重取列表 → 组装 `GridDisplayItem` → `layout.Arrange` → 槽位配色 → 回收 → 复用/实例化 `itemPrefab` 定位 → 溢出处理。
3. **占位**（`InventoryGridLayout`，纯本机、不参与网络）：优先级 = 显式位置 → 上次位置 → 行优先寻位，放不下进 `Overflow`；`TryGetCellOwner` 供交互反查。
4. **物品框**：`BackpackItemUI` 只画主控算好的尺寸/图标/数量/悬停，不做尺寸推导，外观由 `itemPrefab` 决定（UI3 契约）。
5. **交互**：`BackpackInteractionController` 发 `Cmd.*` → `InventoryHostCore.SubscribeCommands` 处理 → 结果靠 `Inv.Changed` 回传；UI 不直接调数据层/网络 API。

## 7. 契约不变式（改动勿破）

1. 位置归数据层；`cells[]` 与 `placements` 同源写入，唯一写点 `CommitPlacement` / `ClearCells`，**无第三份物品列表、无中间态**。
2. 堆叠数单一来源 `RuntimeItem.StackCount`，容器不缓存。
3. 矩形不重叠，尺寸冻结在记录里；**失败即零变更**（先校验后提交）。
4. 广播只在成功路径，source = 容器实例；日志只在变更类操作被拒时写。
5. 网格尺寸非法（非正 / >65536）→ 回退 6×8 并记 Warn。
6. 刻意偏差（对齐蓝本时保留，勿改回源实现）：合并要求双方可堆叠；容量受占堆上限约束；`TryAddItem` 全量吸收；**不提供原地移动**（搬运先移除）。
