## 用户需求

背包系统 UI 左键点击拾起物品后，携带物（跟随光标的预览）应以「被点击的那一格」作为抓取锚点跟随光标，而不是按蓝本口径把物品整体居中吸附到光标所在格。即：抓哪一格，那一格就始终贴在光标下，落点判定也以该格对齐——点 2×3 大剑的左上格，大剑的左上格才跟着光标，不应一拾起就向左上/右下弹出半格。

## 澄清结论（用户已选定）

- 边缘越界：沿用现有「越界不夹取」口径——锚格越出网格时不落位、保持携带，被点格子始终严格在光标下，悬停反馈显示为阻塞（红色）。
- 指针移出网格（或落点推导越界，走自由跟随分支）时：同样让被点格子对准光标（含半格中心偏移），与网格内贴格口径一致，保证出入网格时不跳位。

## 功能范围

- 左键拾起：记录「被点击格相对物品上左格的偏移」，携带期间该偏移固定。
- 网格内：预览按「悬停格 − 抓取偏移」贴格；落点/高亮/红阻判定沿用同一目标索引，故贴边越界自动变红且不可落位。
- 网格外/无落点：预览自由跟随，但以被点格中心对准光标。
- 不改动：堆叠三分支、交换落位、拆分、右键面板、描述面板、网络命令发布与宿主/容器逻辑；不改任何资产、预制体、程序集与 GUID。

## 技术栈

沿用工程既有栈，不引入任何新依赖：Unity 2022.3.62f3 + C#（命名空间 `RPG4.Backpack.*`），改动落在 UI 程序集 `RPG4.Backpack.UI` 的两个既有脚本与两份既有文档；无 asmdef、无 `.meta`、无资产生成需求。

## 实现思路

根因是落点推导走蓝本的「象限 + 取物品中心格」：`BackpackInteractionController.UpdatePointerCache`（L161）每帧调 `grid.GetUpperLeftIndex(tile.TileIndex, tile.Quadrant, carriedDimensions)`，把物品中心格吸附到光标格，拾起瞬间必然跳位（2×3 物品偏 1 格、偶数尺寸还随象限半格抖动）。改为一次性记录「点击格偏移」并在每帧用「悬停格 − 偏移」反推锚格，即可让被点格稳定贴住光标。

关键决策与理由：

1. **偏移记录在拾起时刻**（`BeginCarry`），而非每帧从几何反推——点击格信息只在点击当帧可信（`HandlePrimaryClick` 与本帧 `UpdatePointerCache` 同帧执行），且偏移一旦固定，预览、落点、高亮三处天然一致。
2. **越界不夹取**（用户选定）：不引入 clamp，锚格越界返回 `NoIndex`、区域溢出交给 `QuerySpace` 判 `Blocked`，复用现有判定链，零新增状态机。
3. **自由跟随同口径**（用户选定）：`TrySetCarriedPreviewScreenPosition` 被从「物品半尺寸」改为「被点格中心偏移」，`grabOffset == (0,0)` 时与旧公式完全等价，静态可验证。
4. **象限契约保留**：`TileParams.Quadrant` / `TileQuadrant` / `TryResolveTile` 全部不动（F3 契约类型，`TileParams.IsValid` 依赖象限非 `None`）；仅让携带期间的落点推导不再使用象限，属**有意偏离蓝本**，登记进文档差异表。
5. **性能**：改动全为每帧 O(1) 的整数/浮点算术，无分配、无遍历、无新增订阅；`targetIndex` 仍只在本帧缓存一次供各分支复用，保持既有「每帧一次预计算」结构。

## 实现细节（精确落点）

### 1. `Assets/backpack/Scripts/UI/BackpackGridUI.cs`

- `GetUpperLeftIndex` 签名由 `(int hoverIndex, TileQuadrant quadrant, GridCoord dimensions)` 改为 `(int hoverIndex, Vector2Int grabOffset, GridCoord dimensions)`，语义 = 「锚格 = 悬停格 − 抓取偏移」，换算必须走 `GridUtils.GetPositionFromIndex / GetIndexFromPosition`（去掉移植遗留的裸 `%` / `/`，满足 F4 §5 硬约束）；`hoverIndex` 非法或锚格 < 0（或越出列/行，防御性保留）返回 `SpaceQueryResult<RuntimeItem>.NoIndex`，区域右/下溢出继续交给 `QuerySpace` 判 `Blocked`。注释改为「按抓取格偏移推导上左索引：被点击格贴住悬停格；锚格越界返回 -1（不可放置），不夹取」。
- `TrySetCarriedPreviewScreenPosition` 签名由 `(Vector2 screenPoint, Camera uiCamera, GridCoord dimensions)` 改为 `(Vector2 screenPoint, Camera uiCamera, Vector2Int grabOffset)`（预览尺寸已在 `TryShowCarriedPreview` 写入，`dimensions` 参数冗余）。公式：以 y 向下为正取 `pointerDown = (local.x, -local.y)`，`grabCenterDown = ((grabOffset.x + 0.5f) * pitchX, (grabOffset.y + 0.5f) * pitchY)`（`pitch = cellSize + slotSpacing`，与 `CellToPixel` 同口径），则 `anchoredPosition = new Vector2(pointerDown.x - grabCenterDown.x, -(pointerDown.y - grabCenterDown.y))`。
- 保持不动：`TryResolveTile`（象限照旧）、`QuerySpace`、`SetCarriedPreviewCellPosition`、`CellToPixel` / `ItemPixelSize`、`EnsureCursorLayer`、`ApplyRegionHighlight`。

### 2. `Assets/backpack/Scripts/UI/BackpackInteractionController.cs`

- 携带态新增字段 `private Vector2Int carriedGrabOffset;`（被点击格 − 物品上左格，单位=格，0 基），置于 `carried` 相关字段区并加简洁中文注释。
- `BeginCarry(ItemId id)`：在已有 `grid.TryGetPlacement(id, out GridDisplayPlacement placement)` 之后，用本帧 `tile.TileIndex` 记录偏移（`GridCoord clicked = GridUtils.GetPositionFromIndex(tile.TileIndex, grid.Columns); carriedGrabOffset = new Vector2Int(clicked.X - placement.Position.x, clicked.Y - placement.Position.y);`）；点击格非法或落在物品占格之外时回退 `Vector2Int.zero`（注释说明）。
- `EndCarry()` 与 `ResetSession()` **两处都要复位** `carriedGrabOffset = Vector2Int.zero;`（`ResetSession` 是内联重置携带态、不走 `EndCarry`）。
- `UpdatePointerCache` L161 改为 `targetIndex = grid.GetUpperLeftIndex(tile.TileIndex, carriedGrabOffset, carriedDimensions);`（不携带时 `carriedDimensions == GridCoord.One` 且偏移为零 → `targetIndex == tile.TileIndex`，行为与现状一致）。
- `UpdateCarriedPreview` L259 与 `ResetPointerState` L745 两处自由跟随调用点改传 `carriedGrabOffset`。
- 不改：`UpdateHoverHighlight`（越界/挡路已分别落到 `Blocked` 红）、`TryPlaceCarried` / `PlaceAt`、`ResolveStackOrSwap` 及三个堆叠分支、`SwapPositions`、右键/拆分/命令发布、`OnInventoryChanged`。

## 验证方式

无单测（用户选型）。验证 = IDE 诊断 0 error + 全量确认旧签名 `GetUpperLeftIndex(int, TileQuadrant, GridCoord)` 无残留调用点、`TrySetCarriedPreviewScreenPosition` 三个参数版本无残留调用点；必要时用 Unity 生成的 csproj 对 `RPG4.Backpack.UI` 跑 `dotnet build`（产物重定向到 TEMP）。人工验收按 M6 文档 §四。

## Agent Extensions

### SubAgent

- **code-explorer**
- Purpose: 全量核查改造后的调用面——旧签名 `GetUpperLeftIndex(int, TileQuadrant, GridCoord)` 与三参数 `TrySetCarriedPreviewScreenPosition` 是否零残留调用点，`carriedGrabOffset` 是否在 `BeginCarry` / `EndCarry` / `ResetSession` 三处闭合，以及 `TileParams.Quadrant` 仍被 `TryResolveTile` 与 `IsValid` 正常消费。
- Expected outcome: 输出「残留调用点 0 处 / 跨文件引用仅限两脚本 / 无越界改动」的核查结论，作为验收依据。

### Skill

- **lsp-code-analysis**
- Purpose: 用语义级 find references 定位两个被改方法的所有引用点（含 `BackpackItemPopupView`、输入桥等潜在消费方），避免仅靠文本搜索漏掉别名/间接调用。
- Expected outcome: 得到改动方法的引用清单，确认调用点已全部同步改签名。
