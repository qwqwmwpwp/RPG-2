## 需求概述

把蓝本工程（ZDXT2）已落盘的「物品数据层」（M1：Manifest / Fragment 家族 / 运行时物品）以逐个文件照搬的方式移植进 RPG_4 工程，作为多人背包系统数据链的类型与运行时底座。本轮只交付代码本体与配套工程元文件：不建数据资产、不补标签注册表、不动编辑器工具、不写文档。本轮无界面与表现层内容。

## 核心内容

- 片段家族：片段基座与库存片段基类；标准片段（网格占位 / 图标 / 文本 / 带标签数值 / 可堆叠）；修饰片段（消耗与装备数值项及其容器片段）。
- 物品清单：物品模板资产（模板到运行时实例的创建 / 试创建 / 快照恢复三入口）与「标签到清单」目录资产。
- 运行时：唯一标识与递增生成器、可注入随机源、运行时物品实例（堆叠数单一来源）、数值快照与二进制编解码。
- 其它：消耗效果接口（供后续消耗链调用）与测试程序集可见性声明。
- 每个源码文件配同名工程元文件，导入标识全局唯一（保证 Unity 正确导入）。

## 范围边界

- 包含：13 个源码文件 + 13 个元文件，落盘至 RPG_4 背包脚本的 Items 目录。
- 不包含：示例物品资产、标签注册表补录、编辑器抽屉 / 校验器、任何库存 / 网络 / UI 功能、任何重构或「顺手修复」、任何文档产出、任何既有文件修改。

## 验收标准

1. Unity 刷新后程序集编译通过、Console 无错误。
2. 与蓝本逐文件比对：仅允许的改名行存在差异（全量恰 24 行），其余内容逐字节一致。
3. 新增文件零蓝本命名残留；13 个新导入标识在工程内唯一。

## 技术栈与现状核验

- 工程：Unity 2022.3.62f3 LTS + URP；纯 C#，无第三方依赖；本轮零新包、零 asmdef 改动（`RPG4.Backpack.Items` 已就位，仅引用 `RPG4.Backpack.Core`）。
- 依赖核验（已完成，无缺口）：RPG_4 Core 提供 `BackpackTag`（`Separator` / `GetSegments()` / `MatchesTagExact` / `IsEmpty` / `IsValid` / `Name`）与 `BackpackLog.Warn(LogModule, string)`、`LogModule.Inventory`，覆盖蓝本 13 文件对 Core 的全部引用面。
- 蓝本源（已逐文件细读）：`e:\github\ZDXT2\Assets\backpack\Scripts\Items\`；目标：`e:\ue\RPG_4\Assets\backpack\Scripts\Items\`（asmdef 与四个子目录 .meta 已就位，子目录为空）。

## 实施策略

**逐行照搬 + 4 类改名（全量恰 24 行差异），零行为改动、零重构；每个 .cs 配手工生成的新唯一 GUID .meta。**

## 架构与依赖

- 程序集关系：`RPG4.Backpack.Items → RPG4.Backpack.Core` 单向；不引用 Inventory / UI / 网络；快照编解码显式完成、与网络框架解耦（网络层只搬运 byte[] 载荷）。
- 数据链：`ItemManifest`（模板）→ 深拷贝 + 首次随机化 → `RuntimeItem`（运行时唯一真值，堆叠数单源）→ 抓取 / 编码为载荷；客户端解码 / 恢复为零随机模式。
- 后续消费方：M2 库存真相源（持有 RuntimeItem 列表与占用矩阵）、M3 网络同步（SyncList<struct> 以 ItemId 对齐 + 快照载荷同步数值）；本轮为其铺好类型与运行时基座。

## 实施要点与风险控制

1. 逐字节保真：只做 24 行精确字符串替换；禁止格式化、重排或全文件重写；蓝本注释（含中文）逐字保留。`[skill:command-execution-no-tests-no-comments]` 的「不新增注释」仅指不另行编写注释，不改变复制保真要求；全程不运行任何测试。
2. .meta 手工生成：骨架逐字符对照 `e:\ue\RPG_4\Assets\backpack\Scripts\Core\Tags\BackpackTag.cs.meta`（fileFormatVersion / guid / MonoImporter 完整块，11 行）；GUID 用 `[guid]::NewGuid().ToString("N")` 生成 13 个，落盘后校验互相唯一且全 `Assets` 下不重复。
3. 核对命令（PowerShell，供执行阶段使用）：

- 差异：`Compare-Object (Get-Content 蓝本文件) (Get-Content 目标文件) -SyncWindow 0`，差异条数须等于上表预期。
- 残留：在 `...\backpack\Scripts\Items` 递归搜索 `ZDXT`，期望 0 命中（.cs 与 .meta 都扫）。
- GUID：对 13 个新值逐个在 `e:\ue\RPG_4\Assets` 全量搜索 `guid: 新值`，命中数须为 1（仅自身 .meta）。

4. 爆炸半径控制：目标目录原为空（仅 asmdef 与目录 .meta），新文件无既有引用者，不影响任何现有程序集；不触碰 Core / Data / Docs / 其他程序集；若 Unity 报警告一律记录、不改源码（保真优先）。
