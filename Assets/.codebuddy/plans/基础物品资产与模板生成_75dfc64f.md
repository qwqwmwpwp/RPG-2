## 需求概述

在 RPG_4 背包工程中生成一批基础物品资产（即物品模板）与配套目录资产，全部落在既有的空目录 Data/Items/ 下，为运行时"按类型创建 / 恢复物品实例、拆分取模板、拾取掉落"等流程提供数据基础。

## 核心内容

- 生成 6 件基础物品模板：火蕨果实（材料，1×1 格，单堆上限 64）、小型红药（消耗品，1×1，治疗 10–20，单堆上限 10）、单手剑（装备，1×3，伤害 5–10）、红披风（装备，1×2，护甲 2–5）、铁甲（装备，2×2，护甲 4–8）、大剑（装备，2×3，伤害 12–20）
- 覆盖 1×1 / 1×2 / 1×3 / 2×2 / 2×3 五种网格尺寸，覆盖堆叠 64 / 堆叠 10 / 不可堆叠三种堆叠分支
- 生成 1 个目录资产，把上述 6 件模板全部登记进去，供运行时按类型查找
- 新出现的 2 个物品类型标签补登到标签登记表，保持数据口径一致
- 装备类模板的装备预制体引用留空，待装备阶段再补挂

## 可感知效果

- Unity 编辑器 Project 窗口 Data/Items/ 下出现 7 个资产文件；选中后 Inspector 正常显示物品类型与片段列表（片段、尺寸、数值范围可见可改），无 Missing 脚本、无引用丢失
- 目录资产 Inspector 中显示 6 条登记项，无重复标签警告
- 运行时可用任一模板生成/恢复物品实例，并被拆分、拾取等后续流程按类型找回

## 技术栈

- Unity 2022.3.62f3 LTS 既有工程；复用已落盘的 M1 物品数据模型（ItemManifest / ItemManifestCatalog / 片段家族），不新增任何代码依赖
- 落盘方式：手工编写 .asset（Unity YAML）与 .meta（工程为非 git 仓库，所有 .meta 均需手工生成）
- 格式蓝本：e:/github/ZDXT2/Assets/backpack/Data/Items/ 下已通过 Unity 校验的同结构资产

## 实现方案

1. 以蓝本 4 份资产为格式模板逐字段改写为 RPG_4 口径：m_Script 指向 RPG_4 脚本 GUID（ItemManifest = 4c34e53e651b4930ac2714e72c40d43d，ItemManifestCatalog = 574b717d28d94ff5adfd24a6b5158fc5）；SerializeReference 类型行统一为 ns/asm = RPG4.Backpack.Items（类名用短名）。
2. GUID 策略：3 件对齐资产与目录沿用蓝本 GUID（1f05e9a0… 、11d2a937… 、06b05775… 、30764ee9…，已核对工程内无冲突）；RedCloak、IronArmor、Greatsword 为新资产，现生成新 GUID 并在落盘前全工程查重。
3. 装备片段 equipPrefab 置空引用（fileID: 0），校验不要求非空，M7 装备阶段再挂接预制体。
4. 新增物品标签只追加到 Data/TagRegistry.asset；不改 BackpackTagConstants.cs（该文件自注"其余标签直接加到 TagRegistry"）。Modifier 标签（FragmentTags.Consume.Heal / FragmentTags.Equip.Damage / FragmentTags.Equip.Armor）照蓝本口径使用，蓝本亦未登记，仅需格式合法。
5. 性能与可靠性：纯静态数据资产，零运行时开销；校验完全走既有 ValidateConfiguration 链（标签合法、尺寸、数值范围），无代码改动即无回归面。

## 实现要点（执行细节）

- 每份资产内 rid 引用必须闭合：fragments / modifiers 引用的 rid 与 references.RefIds 一一对应；rid 只需文件内唯一（沿用蓝本数值即可，新资产用任意新数字）
- 序列化字段名必须与源码逐字一致：fragmentTag / itemType 内层用 name；Grid 用 width、height、padding；堆叠用 maxStackSize；装备用 equipmentType、equipPrefab、socketAttachPoint、modifiers；数值项用 label、value、min、max、randomizeOnManifest、collapseLabel、collapseValue、minFractionalDigits、maxFractionalDigits
- 换行 LF、UTF-8 无 BOM；不改任何 .cs / asmdef / 场景 / 预制体；唯一改动既有文件 = TagRegistry.asset 追加 2 行标签
- 不生成图标（工程内无 Sprite 资源）、不做单测（工程选型零单测）、不生成装备预制体、不新增文档

## 架构与数据流

标签登记表（口径）→ ItemManifest 资产（模板：类型标签 + 片段列表）→ ItemManifestCatalog（类型标签到模板的登记目录）→ 运行时消费者（BackpackInventory 与 BackpackNetworkInventory 的 Catalog 字段、库存投影按类型恢复实例）。本轮只补齐"资产侧"一环，全部插入点均为既有序列化字段，无需任何代码改动。

## Agent Extensions

### SubAgent

- **code-explorer**
- Purpose: 对全部新建与改动资产做静态复核——新 GUID 全工程查重、YAML 片段引用闭合、序列化字段名与源码逐字段对照、ns/asm 与标签口径检查
- Expected outcome: 逐项 PASS/FAIL 报告（含问题清单与修正建议），保证 Unity 导入零 Missing、目录登记 6 条无重复警告

### Skill

- **ADHD友好输出**
- Purpose: 交付说明按"行动先行、编号步骤、无开场白无结束语"格式给出
- Expected outcome: 完成后第一句即给结果与下一步（Unity 刷新验收步骤），信息密度优先
