## Product Overview

移除背包 UI 中「悬停物品描述面板」与「右键操作弹窗」两套已实现（后者此前已下线）的脚本组件，并清空交互控制层中与之耦合的悬停描述逻辑，为使用者自行重写这两块界面腾出干净、可编译的接口，同时不改动场景与文档。

## Core Features

- **删除三个 UI 脚本**：悬停描述面板、右键操作弹窗、描述内容数据类，连同各自的 `.meta` 一并删除，文件名与 GUID 全部释放
- **清空控制器描述逻辑**：移除交互控制层中的描述面板接线字段、延迟时长常量、描述刷新方法与面板命中判定方法、两个描述状态字段，以及 `ResetPointerState` 的「保留面板」形参，连带修正全部调用点
- **交互行为收敛**：删除后，指针不再有「落在面板上就丢弃点击」的分支，每帧更新链只保留指针缓存、悬停物品、悬停高亮、携带预览与输入分派五步
- **场景与文档保持原样**：场景中两个已挂空组件的占位节点、控制器上的面板引用行、里程碑文档中的相关描述均不动，由使用者自行接管
- **结果可验证**：删除完成后全仓无残留引用，UI 程序集编译通过

## Tech Stack

- 引擎与语言：Unity 2022.3.62f3 LTS + URP，C#（沿用现状，无新增依赖）
- 目标程序集：`RPG4.Backpack.UI`（`Assets/backpack/Scripts/UI/RPG4.Backpack.UI.asmdef`）；本次删除不涉及 asmdef 改动
- 校验手段：命令行 `dotnet build RPG4.Backpack.UI.csproj`（Unity 生成的 csproj，产物重定向到 TEMP）作为编译门禁；本项目 C# 不走 Open Code Review（该工具仅覆盖 TS/JS/Python/Java/Go/Kotlin），自检改人工审计

## Implementation Approach

纯删除式改造，分两处动作，最终必须同时完成否则编译报错：

1. **控制器就地瘦身**（唯一代码编辑点）：`BackpackInteractionController.cs` 删除全部 description 相关成员与调用点，其余逻辑零改动。
2. **文件级删除**：3 个脚本 + 3 个同名 `.meta`。

关键决策：

- **`.meta` 一并删除**（用户选型）：旧 GUID 释放，Unity 重新生成；代价是场景中挂载这两组件的两个占位节点会显示为 missing script，由用户自行处理。
- **控制器不留接缝**（用户二次确认）：字段、常量、方法、状态字段、形参全部删除，不保留占位或临时类型，删完即可直接编译，使用者后续自行设计新接口。
- **场景与文档不动**（用户选型）：「其余我自己改」，因此场景序列化行与 M6 里程碑文档保持原样。控制器的 `description: {fileID: 1916202766}` 序列化行在字段删除后由 Unity 自动丢弃，不会报错。
- **`ResetPointerState` 形参删除后展开条件块**：原 `if (!keepDescription) { ... }` 包裹块展开为无条件执行，保证「指针不可用时复位悬停物 / 高亮 / 携带预览」的行为与原 `keepDescription = false` 路径逐行等价。`keepDescription: true` 的唯一调用点随第 152–157 行整段分支一起删除，删后全仓无残留命名参数。
- **行为影响评估**：删除的每帧 `ContainsScreenPoint` 面板命中判定与 `UpdateDescription` 调用使每帧计算量小幅下降，无新增分配、无 GC 影响、无性能风险。副作用是失去「指针在面板上时网格不分派点击」的保护——该保护本就依附于面板本体，会随使用者自研面板一并恢复。
- **技术债（有意留白，不属本次范围）**：`BackpackFeedbackPalette.TextMuted` 在删除描述面板后失去唯一调用方；M6 文档第 19/21/28/86–88/95 行附近仍有描述面板与弹窗的过期描述；二者本轮均不清理。

## Architecture Design

不引入任何新架构模式，仅在现有 M6 交互层内部做减法。每帧更新链由

`指针可用性 → 面板命中判定（提前 return） → 指针缓存 → 悬停物品 → 悬停高亮 → 携带预览 → 描述刷新 → 输入分派`

收敛为

`指针可用性 → 指针缓存 → 悬停物品 → 悬停高亮 → 携带预览 → 输入分派`

其余链路（网格主控、事件管线、`Cmd.Item.*` 意图、本地携带与右键拆分、单机 / 联机宿主）完全不受影响。变更面单一、可逆，无图必要。

### Skill

- **command-execution-no-tests-no-comments**
- Purpose: 约束本次编辑只做删除、不新增任何代码注释，且不创建或运行测试（本项目零单测口径），避免为删除动作写解释性注释污染源码。
- Expected outcome: 改动后的 `BackpackInteractionController.cs` 中，被删位置不留空注释或「已移除」说明，工程内不产生任何新测试文件。

- **ADHD友好输出**
