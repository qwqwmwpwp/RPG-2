## 需求概述

为 RPG_4 多人背包系统落盘 M3 网络同步：服务端权威库存以增量方式同步给所属客户端，两端物品列表、堆叠数与随机数值完全一致；客户端仅提交操作意图，不得篡改库存；网格位置不参与网络同步。

## 核心内容

- 物品运行时快照：数值抓取 / 编码 / 解码 / 回填，客户端恢复不重新随机化
- 库存增量同步：同步条目按唯一 ItemId 对齐，增删改差异下发，晚加入客户端可收敛
- 客户端命令复核：改堆叠 / 移除走 Command，越权越界一律拒绝并记录原因
- 开发冒烟面板：Host / Client 双端手动操作与只读镜像展示
- 验收方式：Unity 编译 + 双端人工核对（零单测）
- 交付要求：方案精简，只含落盘清单 / 执行顺序 / 裁剪登记 / 验收 / 偏差五段

## 技术栈

- Unity 2022.3.62f3 + Mirror 96.0.1（工程内已内置，直接引用，不新增任何包）
- 既有六程序集 `RPG4.Backpack.*`（Core / Items / Inventory / Equipment / UI / Network），本轮只动 Items 与 Network
- 手工 `.meta`（GUID 沿用蓝本同名文件，先全量搜索确认无冲突）；全工程不得引用 `Unity.InputSystem`

## 实现方式

1. 逐文件照搬蓝本（e:/github/ZDXT2）+ 前缀替换 `ZDXT.Backpack.*` → `RPG4.Backpack.*`；核心文件按已核实行号裁剪为 M3-only。
2. 依赖方向：`Items → Inventory → Network →（预制体 / 场景）`；数据层不引用 Mirror。
3. 权威模型（修正项 A）：客户端只发 Command 意图 → 服务端复核改容器 → 复制回；网格位置完全不参与复制（修正项 B）；堆叠数单一来源（K）。

## 关键实现要点

- 保留面：`SyncList&lt;NetworkInventoryEntry&gt;`、两个 Command（改堆叠 / 移除）、TryServerAddItem / TryServerSetStackCount / TryServerRemoveItem / TryServerClearInventory / SyncNow / RefreshClientMirror、TryGetItem / CopyItems / ItemCount / IsServerInventory、Changed 脏标记 + LateUpdate 合并触发一次
- 客户端恢复只回填数值（TryRestoreRuntimeItem → TryApplyNumbers → TryApplyRuntimeNumber），全程不调用 IItemRandomSource
- 投影以「本次操作的物品是否进入投影」判定成败；其它拒绝只累计 DesyncCount / LastError，不误回滚
- 同步按 ItemId 升序做差异（Add / Set / RemoveAt），无变化零下发；Id 索引字典平均 O(1)；载荷长度 / 节点数 / 堆叠范围 / 类型串长度全有边界校验
- F6 频道零新增（`Cmd.Item.Drop` / `Cmd.Item.Consume` 已有）；客户端镜像变化走 BackpackNetworkInventory.Changed，M5 接线时再定 UI 订阅口径

## 验收（人工双端，零单测）

1. Unity 刷新编译无报错；Weaver 为 NetworkInventoryEntry 生成读写器
2. Host：添加 / 改堆叠 / 移除 / 清空 → 条目增改删；客户端请求经服务端复核后两端同步
3. 第二实例 Client 晚加入：列表完整、随机数值与 Host 完全一致、不重随机
4. 越界越权（超 MaxStackSize / 小于等于 0 / 不存在 Id）被拒且两端不变；断线重连镜像不残留

## 偏差与风险

- 零单测：蓝本 8 个投影用例不移植（Tests/Network 空目录保留），M9 回归轮再定
- 位置不同步为已知缺口（修正项 B），M3 不补字段，仅在文档登记
- 冒烟面板为开发件，M5 落地正式 UI 后不复用
- 场景 / 预制体 / 物品资产由用户手搭：Data/Items 建 2–3 个 Manifest（建议带随机化数值以验「不重随机」）+ ItemManifestCatalog 资产；PF_NetworkPlayer 挂 BackpackNetworkInventory（rows 6 / columns 8）
